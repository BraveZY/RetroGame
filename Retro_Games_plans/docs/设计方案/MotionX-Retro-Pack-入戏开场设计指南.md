# MotionX Retro Pack / 开场与入戏层级设计指南

> 本文统一定义 `MotionX Retro Pack / 复古体感包` 的产品启动、主题入场和单游戏入戏三层开场关系。它补充 [用户体验旅程](./MotionX-Retro-Pack-用户体验旅程.md) 中的“回忆开场”节点，以及 [单个复古体感游戏标准流程_参考](../单个复古体感游戏标准流程_参考.md) 中的 10-20 秒开场要求。

## 1. 核心结论

| 项目 | 定义 |
| --- | --- |
| 推荐命名 | 入戏开场 |
| 作用 | 在进入某一个具体游戏前，用声音、画面和一句话把用户带入具体场景 |
| 时长 | 10-20 秒 |
| 体验目标 | 让用户觉得自己正在进入某一个已选择的具体游戏，而不是打开一个普通运动小游戏 |
| 制作原则 | 低成本、短时长、强场景、少解释、可跳过或可快速进入 |
| 首版优先级 | P0，每个样板游戏都需要至少一套入戏开场 |

一句话：

> 入戏开场不是剧情播片，而是让用户站起来之前先知道“我在哪里、我是谁、为什么要动”。

## 2. 三层开场职责

```text
产品层
  -> 主题层
  -> 游戏层
```

| 层级 | 触发点 | 时长 | 设计职责 | 不承担什么 |
| --- | --- | ---: | --- | --- |
| 产品层 | 启动产品 | 立即进入 | 品牌识别、健康提示、登录或首页入口 | 不播放完整怀旧长开场，不讲 80/90 背景 |
| 主题层 | 点击主题馆后 | 2-4 秒 | 用声音、画面和一句短文案建立主题氛围 | 不展示具体规则，不做站位识别，不串联多个游戏 |
| 游戏层 | 选择具体游戏后 | 10-20 秒 | 建立这一局的场景、身份、动作理由和站位倒计时 | 不介绍整个主题馆，不提示下一局 |

一句话：

> 产品启动解决“今天去哪玩”，主题入场解决“进入什么回忆场景”，单游戏入戏解决“这一局具体怎么玩”。

### 2.1 主题入场结构

```text
声音触发
-> 场景落点
-> 主题主页出现
```

| 段落 | 时长 | 作用 | 要求 |
| --- | ---: | --- | --- |
| 声音触发 | 0.5-1 秒 | 立刻标记主题 | 下课铃、投币声、电视开机声等原创抽象化音效 |
| 场景落点 | 1-2 秒 | 建立空间 | 操场、电视、街机灯牌等主题锚点 |
| 主题主页出现 | 0.5-1 秒 | 进入可操作页面 | 显示主题名、推荐内容、游戏列表或挑战入口 |

首批主题入场：

| 主题 | 声音 | 画面 | 短文案 | 落点页面 |
| --- | --- | --- | --- | --- |
| 童年操场 | 下课铃原创变体、远处跑动声、操场广播 | 阳光、教学楼、跑道、国旗台、粉笔线 | 上午课间 | 操场主题主页：操场木头人、跳房子、丢手绢、丢沙包 |
| 客厅街机 | 咔哒、电视开机、频道切换、投币声 | 老电视亮起、街机灯牌、分数板跳动 | 今日挑战 | 街机主题主页：投篮机、拳击机、反应挑战、高分榜 |
| 家庭电视健身 | 电视节目开场音、原创广播操前奏、轻节拍 | 晚上七点、客厅电视、家庭成员站到电视前 | 晚上七点 | 电视健身主题主页：家庭电视健美操、拳击操、亲子拉伸 |

判断标准：

| 问题 | 通过标准 |
| --- | --- |
| 是否过长 | 2-4 秒内结束，可快速进入操作 |
| 是否挡住选择 | 只在点击主题后出现，不在产品启动时强制播放 |
| 是否区分主题 | 不同主题有不同声音、镜头和落点 |
| 是否混淆单游戏开场 | 不出现具体游戏规则、站位识别或倒计时 |

## 3. 使用边界

本文只解决“单个游戏怎么开始得更有场景感”，不负责把多个游戏串成一条路线。

| 边界项 | 本文负责 | 本文不负责 |
| --- | --- | --- |
| 产品层级 | 单个游戏 / 单个课程开始前的 10-20 秒入戏 | `童年的一天` 这种多游戏路线编排 |
| 用户问题 | 我现在进入的这一局在哪里、我是谁、为什么动 | 今天先玩哪个、下一个接哪个、整条路线怎么走 |
| 设计内容 | 声音触发、场景出现、身份确认、动作理由、站位倒计时 | 时段顺序、内容推荐、playlist、跨游戏转场、主题馆内多个游戏展示 |
| 首版用途 | 让操场木头人、投篮机、家庭电视健美操各自开局成立 | 把三个样板强行串成完整一天 |
| 相关文档 | 单局流程、用户旅程里的“回忆开场”节点 | `童年的一天_云端内容编排关系.md` 和结构蓝图 |

如果后续激活 `童年的一天`，它负责决定“这一段路线进入哪个内容”；本文只在用户真正进入某一个内容时，提供这一局的入戏开场模板。

另一个同样重要的边界：

> 用户进入一个主题馆后，只能选择一个具体游戏。入戏开场只表现这个被选中的游戏，不能把同主题馆里的多个游戏一起展示出来。

## 4. 标准结构

建议所有入戏开场都按 5 段式设计。

```text
声音触发 2-3 秒
-> 场景出现 3-5 秒
-> 身份确认 2-4 秒
-> 动作理由 2-4 秒
-> 站位 / 倒计时 3-5 秒
```

| 段落 | 目的 | 设计方式 | 示例 |
| --- | --- | --- | --- |
| 声音触发 | 先唤起记忆和注意力 | 下课铃、投币声、电视雪花、锣鼓、人群声 | 下课铃一响，用户知道进入课间 |
| 场景出现 | 让用户知道自己在哪里 | 操场、街机厅、老电视、游园摊位逐步亮起 | 黑板、跑道、投篮机灯牌、电视节目标题 |
| 身份确认 | 让用户知道自己扮演什么 | 同学、挑战者、电视前跟练的家庭成员、游园摊位玩家 | “站到队伍里”“投币成功”“站到电视前” |
| 动作理由 | 让动作不只是指令 | 跑停、投篮、跟做、套圈、躲闪都要变成场景行为 | “老师看过来了，别动”“灯牌亮了，限时投篮” |
| 站位 / 倒计时 | 顺滑进入识别和游戏 | 用场景语言包装校准和倒计时 | “准备上场”“站到挑战区”“广播开始了” |

## 5. 单游戏开场设计方法

入戏开场必须从“已选择的游戏”出发，而不是从主题馆出发。主题馆只提供背景语汇，不能在同一个开场里同时出现多个玩法。

| 设计项 | 正确做法 | 错误做法 |
| --- | --- | --- |
| 入口关系 | `主题馆 -> 选择一个游戏 -> 该游戏入戏开场` | `主题馆 -> 播一段把多个游戏串起来的开场` |
| 画面元素 | 只出现当前游戏需要的目标物、站位区和动作提示 | 同时出现套圈、沙包、保龄球、投篮、拳击等多个游戏元素 |
| 文案 | 只说明这一局要做什么 | 介绍整个主题馆里有哪些玩法 |
| 声音 | 服务当前游戏节奏 | 把不同游戏的音效混成合集 |
| 用户理解 | 我现在要玩这一局 | 我是不是要连续玩一串游戏 |

单游戏开场可以借用主题馆的氛围，但必须把当前游戏的目标说清楚：

| 当前游戏 | 可借用的主题氛围 | 开场中只能突出的游戏元素 |
| --- | --- | --- |
| 操场木头人 | 下课铃、操场、队伍线、广播 | 起跑线、老师视线、跑停提示 |
| 电玩城投篮机 | 投币声、灯牌、分数板 | 篮筐、篮球、限时计分 |
| 家庭电视健美操 | 电视雪花、节目标题、节拍 | 动作预览、跟做节拍、站位区 |
| 套圈 | 游园摊位、奖券、叫卖声 | 套圈、目标奖品、投掷线 |
| 扔沙包 | 游园摊位、目标牌、欢呼声 | 沙包、靶子、命中区 |

## 6. 单游戏脚本示例

### 6.1 操场木头人

```text
0-2 秒：下课铃响，画面从客厅电视切到操场。
2-5 秒：教学楼、跑道和粉笔线出现，远处有孩子跑过。
5-8 秒：广播声：“课间游戏开始，站到队伍里。”
8-12 秒：起跑线亮起，玩家颜色区出现。
12-16 秒：提示：“跑得快，也要停得稳。”
16-20 秒：老师口哨声，倒计时进入：3、2、1。
```

用户应该理解：

| 问题 | 答案 |
| --- | --- |
| 我在哪里 | 童年操场 / 课间 |
| 我是谁 | 准备玩课间游戏的同学 |
| 我为什么跑 | 下课后冲向游戏 |
| 我为什么停 | 老师看过来了，要变成木头人 |

### 6.2 电玩城投篮机

```text
0-2 秒：投币声响，街机灯牌点亮。
2-5 秒：分数板从 0000 跳动，投篮框亮起。
5-8 秒：机器音：“挑战机启动。”
8-12 秒：站位区出现，提示：“站到挑战区。”
12-16 秒：倒计时牌亮起，提示：“今天看看谁能上榜。”
16-20 秒：音乐加速，投篮目标出现，进入游戏。
```

用户应该理解：

| 问题 | 答案 |
| --- | --- |
| 我在哪里 | 放学后的街机 / 投篮机前 |
| 我是谁 | 限时挑战高分的玩家 |
| 我为什么伸手 / 挥臂 | 投篮命中、冲排行榜 |
| 成功像什么 | 灯牌爆亮、分数上墙 |

### 6.3 家庭电视健美操

```text
0-2 秒：电视雪花闪一下，频道切换。
2-5 秒：节目标题出现：“家庭运动时间”。
5-8 秒：原创复古节拍进入，电视里的教练剪影抬膝挥臂。
8-12 秒：提示：“站到电视前，跟上节拍。”
12-16 秒：家庭成员站位区出现，动作预览出现。
16-20 秒：节目口令：“第一节，准备开始，3、2、1。”
```

用户应该理解：

| 问题 | 答案 |
| --- | --- |
| 我在哪里 | 家庭客厅 / 老电视前 |
| 我是谁 | 跟着电视一起运动的家庭成员 |
| 我为什么抬膝挥臂 | 跟着节目节拍做动作 |
| 成功像什么 | 全家节拍对上了 |

### 6.4 套圈

```text
0-2 秒：游园摊位灯亮起，只出现套圈摊位。
2-5 秒：目标奖品摆到桌面，投掷线亮起。
5-8 秒：摊位叫卖声：“套圈挑战开始。”
8-12 秒：玩家站位区出现，提示：“站到线后。”
12-16 秒：第一个目标奖品闪光，提示：“看准目标，再出手。”
16-20 秒：倒计时鼓点进入，第一轮套圈开始。
```

用户应该理解：

| 问题 | 答案 |
| --- | --- |
| 我在哪里 | 游园会的套圈摊位 |
| 我是谁 | 轮到出手的挑战者 |
| 我为什么伸手 / 摆臂 | 把套圈投向目标奖品 |
| 成功像什么 | 套中奖品、摊位欢呼 |

注意：套圈开场里不应该出现沙包、保龄球或其他摊位目标，否则用户会误以为这是多个游园游戏串联。

## 7. 画面、声音、文案分工

| 维度 | 负责什么 | 要求 |
| --- | --- | --- |
| 画面 | 建立场景和玩家站位 | 明亮、清楚、3 米外可读，不做昏暗旧照片 |
| 声音 | 触发记忆和节奏 | 原创音效；下课铃、投币声、电视开机声可以抽象化处理 |
| 文案 | 说明身份和动作理由 | 一句话为主，不解释背景历史 |
| UI | 引导进入识别和倒计时 | 使用“站到队伍里”“准备上场”等场景语言 |
| 音乐 | 从开场自然过渡到游戏节奏 | 不使用真实老歌，不模仿名曲旋律 |

## 8. 文案规则

### 8.1 推荐句式

| 句式 | 示例 |
| --- | --- |
| 场景 + 动作 | 下课了，站到队伍里。 |
| 身份 + 任务 | 今天轮到你挑战高分。 |
| 目标 + 情绪 | 全家一起跟上节拍。 |
| 规则包装 | 老师看过来了，别动。 |
| 倒计时包装 | 广播开始了，3、2、1。 |

### 8.2 不推荐句式

| 不推荐 | 原因 |
| --- | --- |
| 正在识别人体，请保持站立 | 技术感太强，破坏入戏 |
| 这是 80/90 后童年经典回忆 | 像介绍词，不像游戏开场 |
| 请完成校准以进入运动识别系统 | 太工程化 |
| 这里有很多怀旧玩法等你体验 | 泛，不给动作理由 |
| 观看完剧情后开始游戏 | 暗示等待成本高 |

## 9. 制作复用方式

首版可以复用主题馆的视觉语汇和基础音效，但不能复用成“主题馆合集开场”。正确复用方式是“同一套场景语言 + 当前游戏专属目标物”。

```text
主题馆视觉语汇
+ 当前游戏专属目标物
+ 当前游戏动作提示
+ 当前游戏站位 / 倒计时
```

| 可复用 | 必须按游戏替换 |
| --- | --- |
| 操场氛围、下课铃、广播质感 | 木头人的老师视线 / 跳房子的格子 / 躲沙包的沙包轨迹 |
| 街机灯牌、投币声、分数板质感 | 投篮机的篮筐 / 拳击机的拳击靶 / 打地鼠的目标洞 |
| 电视开机、节目包装、节拍质感 | 健美操的动作预览 / 拳击操的出拳提示 / 拉伸的慢动作提示 |
| 游园摊位、奖券、叫卖声 | 套圈的目标奖品 / 扔沙包的靶子 / 保龄球的球道 |

判断标准：

| 问题 | 通过标准 |
| --- | --- |
| 这段开场是否只服务一个游戏？ | 看完后用户只知道自己要玩一个明确游戏 |
| 是否出现了其他游戏的目标物？ | 不出现，最多作为背景氛围的模糊装饰，不能成为可交互目标 |
| 是否像主题馆介绍片？ | 不像，文案不介绍“这里有很多玩法” |
| 是否像路线串联？ | 不像，不提示下一个游戏，也不承诺连续挑战 |

## 10. 验收标准

| 验收项 | 通过标准 |
| --- | --- |
| 时长 | 10-20 秒内完成，不拖慢首局进入 |
| 场景理解 | 用户 5 秒内知道自己在哪里 |
| 动作理解 | 用户进入倒计时前知道接下来大概要做什么 |
| 技术隐藏 | 不出现骨骼、算法、校准等技术词 |
| 亲子适配 | 家长能产生发起理由，孩子也能看懂 |
| 大屏可读 | 关键字、站位区、倒计时 3 米外可读 |
| 版权安全 | 不使用真实老歌、真实 IP、可识别影视/街机/动画元素 |
| 可复用 | 可复用主题氛围资产，但目标物、动作提示、站位文案必须按当前游戏替换 |
| 主题入场 | 2-4 秒内进入主题主页，不讲具体游戏规则 |

## 11. 设计红线

| 不做 | 原因 |
| --- | --- |
| 1 分钟以上剧情动画 | 短局用户等不住，也不符合 MVP 目标 |
| 大段介绍童年背景 | 孩子不关心，家长也不需要被教育 |
| 技术校准语言外露 | 会把入戏体验拉回设备操作 |
| 过度昏暗、泛黄、重噪点 | 影响电视可读性，也降低孩子接受度 |
| 每个游戏开场完全不同 | 制作成本高，主题馆一致性差 |
| 每个游戏开场完全一样 | 用户会觉得只是换皮 |
| 在一个开场里展示同主题馆多个游戏 | 用户会误解为进入主题后要连续玩一串游戏 |
| 用主题馆介绍片替代单游戏开场 | 用户不知道当前这一局具体要做什么 |
| 依赖真实音乐或真实 IP | 版权和渠道审核风险高 |
| 产品启动播放必看怀旧长动画 | 拖慢进入选择，也让回流用户反感 |
| 用主题入场替代单游戏入戏 | 用户不知道这一局具体要做什么 |
