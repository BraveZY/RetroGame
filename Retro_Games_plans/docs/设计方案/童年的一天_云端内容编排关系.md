# 童年的一天：云端内容编排关系

> 本文用于明确 `童年的一天` 与 `童年操场`、`客厅街机`、`电视健美操` 等主题馆之间的关系。它统一承接情绪时间线、内容来源、云端配置、客户端呈现和首发阶段边界，不替代产品定义。

## 1. 核心结论

`童年的一天` 不是一个独立内容包，也不是与 `童年操场`、`客厅街机`、`电视健美操` 平级的主题馆。

它应该被定义为一个基于云端内容池的编排层：

- `童年操场`、`客厅街机`、`电视健美操` 是内容分类和主题馆。
- `童年的一天` 是把这些内容按时间、情绪和运动强度串起来的一条体验路线。
- 云端负责提供内容、标签和推荐编排。
- 客户端负责展示、下载、缓存、运行和结算。

一句话：

> 主题馆负责装内容，童年的一天负责把内容串成一次有记忆点的家庭体验。

## 2. 结构关系

```text
云端内容池
  ├─ 童年操场
  │   ├─ 操场木头人
  │   ├─ 跳房子
  │   ├─ 丢手绢
  │   └─ 跑跑停停
  │
  ├─ 客厅街机
  │   ├─ 电玩城投篮机
  │   ├─ 拳击机
  │   ├─ 打地鼠
  │   └─ 街机闪避跑
  │
  └─ 电视健美操
      ├─ 家庭电视健美操
      ├─ 拳击操
      ├─ 亲子拉伸
      └─ 低冲击跟练

客户端体验层

      ├─ 清晨·上学路上
      ├─ 上午·课间操场
      ├─ 下午·放学之后
      ├─ 傍晚·回到家里
      └─ 周末·节日游园
```

## 3. 主题馆和童年的一天的分工

| 对象 | 定位 | 主要职责 | 是否直接生产内容 |
| --- | --- | --- | --- |
| 童年操场 | 主题馆 / 内容分类 | 承载课间、操场、亲子多人类游戏 | 是 |
| 客厅街机 | 主题馆 / 内容分类 | 承载投篮机、拳击机、打地鼠、排行榜类短局 | 是 |
| 电视健美操 | 主题馆 / 内容分类 | 承载家庭跟练、低冲击健身、亲子同步类内容 | 是 |
| 童年的一天 | 编排层 / 播单层 / 体验路线 | 从主题馆内容中选取游戏，按一天的情绪节奏串联 | 否 |

因此，`童年的一天` 不应该拥有一套和主题馆重复的内容目录。它引用已有内容，并给这些内容安排一个新的体验顺序。

## 4. 一天时间线如何取内容

| 时间段 | 体验目标 | 主要内容来源 | 示例 |
| --- | --- | --- | --- |
| 清晨·上学路上 | 慢热、入戏、轻校准 | 电视健美操 / 童年操场中的轻量热身内容 | 踏步赶路、晨间伸展、广播体操前奏 |
| 上午·课间操场 | 热闹、多人、跑跳停 | 童年操场 | 操场木头人、跳房子、丢手绢、跑跑停停 |
| 下午·放学之后 | 爽感、竞技、刷分 | 客厅街机 | 投篮机、拳击机、打地鼠、街机闪避跑 |
| 傍晚·回到家里 | 降强度、亲子陪伴、跟练 | 电视健美操 | 家庭电视健美操、亲子拉伸、低冲击跟练 |
| 周末·节日游园 | 番外、活动、奖励 | 童年操场 / 客厅街机 / 节日活动内容 | 套圈、扔沙包、保龄球、节日挑战 |

这里的关键不是把每个主题馆固定塞进某一个时间段，而是让云端根据内容标签选择合适的游戏：

- 同一个主题馆的内容可以出现在多个时间段。
- 同一个时间段也可以混合多个主题馆的内容。
- 编排依据优先是场景、动作强度、家庭参与方式和情绪节奏，而不是只看主题馆名字。

### 4.1 情绪时间线

| 时段 | 情绪关键词 | 节奏 | 设计作用 |
| --- | --- | --- | --- |
| 清晨·上学路上 | 睡眼惺忪、轻快、出发 | 慢热、单人热身 | 把站位和轻校准包装成“背好书包准备出门” |
| 上午·课间操场 | 集体、奔跑、热闹 | 中高强度、多人 | 第一个能量爆发点，证明跑、停、跳、躲都有课间理由 |
| 下午·放学之后 | 自由、竞技、刷分 | 高强度、刷分 | 一天里的爽感高点，承接街机和排行榜动机 |
| 傍晚·回到家里 | 温馨、慢下来、亲子 | 中低强度 | 从竞技收回到陪伴和轻健身 |
| 周末·节日游园 | 狂欢、彩蛋、奖励 | 轻松、趣味 | 番外活动和 Game Pass 更新口 |

情绪弧：

```text
慢热 -> 热闹 -> 最嗨 -> 温柔收尾 -> 周末彩蛋
```

每个时段都必须补齐五个体验要素：

| 要素 | 说明 |
| --- | --- |
| 场景 | 用户在哪里，例如操场、街机、小卖部、客厅电视、游园摊位 |
| 身份 | 用户扮演谁，例如同学、挑战者、家庭成员、摊位玩家 |
| 动作理由 | 动作为什么成立，例如跑停是红灯绿灯，挥臂是投篮或套圈 |
| 反馈语言 | 成功和失败如何说，例如老师没发现、投币机爆灯、全家节拍对上 |
| 结算记忆 | 结束后记住什么，例如课间小冠军、放学高分王、家庭电视健身队 |

## 5. 云端应该配置什么

云端至少需要维护两类数据。

### 5.1 内容条目

每个游戏或课程作为一个内容条目，带有主题、动作、强度、人数和时间线标签。

```text
content_id: freeze_playground
title: 操场木头人
theme: 童年操场
time_slots:
  - 上午·课间操场
motion_tags:
  - RunStop
  - FreezeStill
players: 1-4
duration: 90秒
intensity: 中高
status: 首发样板
```

### 5.2 编排路线

`童年的一天` 是一条可由云端下发的路线配置。

```text
playlist_id: childhood_day_default
title: 童年的一天
slots:
  - slot: 清晨·上学路上
    content: 晨间伸展
  - slot: 上午·课间操场
    content: 操场木头人
  - slot: 下午·放学之后
    content: 电玩城投篮机
  - slot: 傍晚·回到家里
    content: 家庭电视健美操
  - slot: 周末·节日游园
    content: 套圈挑战
```

客户端不应该把这条路线写死。客户端只需要识别云端下发的时段、内容 ID、展示文案、资源地址和运行参数。

## 6. 客户端应该怎么呈现

客户端可以有两种入口。

### 6.1 主题馆入口

用户直接选择某个主题馆：

```text
首页
  -> 童年操场
      -> 操场木头人
      -> 入戏式识别
      -> 游戏中
      -> 结算
```

这个入口适合首发阶段，理解成本最低。

### 6.2 童年的一天入口

用户选择一条被编排好的体验路线：

```text
首页
  -> 童年的一天
      -> 清晨·上学路上
      -> 上午·课间操场
      -> 下午·放学之后
      -> 傍晚·回到家里
      -> 周末·节日游园
```

这个入口适合内容量足够后上线。它不要求用户必须完整通关，也不应该做成重剧情任务。用户可以从任意时段进入，也可以只玩其中一段。

## 7. 阶段边界

| 阶段 | 推荐形态 | 原因 |
| --- | --- | --- |
| MVP 3 个样板 | 主题馆入口 + 弱时段标签 | 内容量少，完整时间线容易显空 |
| 首发 6-10 个内容 | 主题馆内容扩展 + 弱推荐顺序 | 内容池开始稳定，但仍不做强制通关时间线 |
| 成长期 10-20 个内容 | 激活 `童年的一天` 编排入口 | 每个时段能放 2-4 个内容，路线开始成立 |
| 成熟期 20+ 个内容 | 云端多路线 + 活动编排 | 可以做周末版、亲子版、低强度版、节日版 |

首发阶段可以在主题馆内容上先埋好 `time_slots` 标签，但不必把 `童年的一天` 做成主入口。

## 8. 设计红线

1. 不把 `童年的一天` 做成第四个主题馆。
2. 不在客户端写死一套固定内容顺序。
3. 不为 `童年的一天` 复制一份与主题馆重复的内容库。
4. 不强制用户按时间线通关。
5. 不因为时间线存在，就取消 `童年操场`、`客厅街机`、`电视健美操` 的直接入口。
6. 不用剧情、等级、装备或复杂任务系统撑起时间线。
7. 不把“走完一天”做成通关任务；它是可选串玩挑战。
8. 不让同一动作原语只靠换背景重复出现，必须通过目标、节奏或场景拉开体验。

## 9. 产品表达

对用户侧可以这样表达：

> 今天不只选一个游戏，而是跟着爸妈小时候的一天，玩过上学路、课间操场、放学街机和晚上的客厅电视。

对产品和工程侧应这样理解：

> `童年的一天` 是云端对主题馆内容的一次体验编排，不是新的内容分类。

## 10. 与现有文档关系

- 产品定义继续负责说明 `MotionX Retro Pack` 的整体定位、首批主题馆和样板游戏。
- 本文负责说明 `童年的一天` 的情绪时间线、成长阶段、云端内容池取数和客户端呈现。
- MVP 与系统模块分层方案只保留 `童年的一天` 的 P2 归位和红线，不重复维护编排细节。
