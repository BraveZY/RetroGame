# MotionX Retro Pack / 微信分享模块设计文档

> 本文用于定义 `MotionX Retro Pack / 时光体感馆` 的微信分享模块。该模块服务于结算回忆、家庭挑战、节日活动和渠道回流，不承担核心玩法、不替代账号系统，也不作为奖励裂变或付费刺激系统。

## 1. 模块定位

微信分享模块的核心目标是把“玩完后的家庭记忆”和“可再次参与的活动入口”带到微信关系链中，让用户愿意保存、转发和邀请亲友参与。

设计原则：

1. 分享是结果表达，不是强制任务。
2. 分享不作为领取儿童奖励、解锁玩法或提高分数的前置条件。
3. 分享内容围绕分数、称号、回忆标签、挑战邀请和活动入口，不暴露儿童敏感信息。
4. 移动端直接调起微信；大屏端通过二维码把分享动作交给手机完成。
5. 分享链路必须服从实名、防沉迷、隐私政策、儿童隐私和渠道审核要求。

## 2. 分阶段范围

| 阶段 | 能力范围 | 不做内容 |
| --- | --- | --- |
| MVP | 生成结算回忆卡片图片；支持保存到本地相册或系统分享面板；预留分享内容 ID 和埋点结构 | 不接正式微信 SDK；不做分享得奖励；不做邀请任务；不做实时合影分享 |
| 首发 | 接入微信好友、微信群、朋友圈；支持挑战邀请、活动海报、二维码落地页；记录基础分享和回流事件 | 不抓取通讯录；不做关系链画像；不做强制裂变；不把儿童奖励商业化 |
| 成长期 | 支持每周家庭挑战、节日活动、Game Pass 活动的分享回流和效果归因 | 不把分享变成主玩法；不以拉人数量作为儿童奖励条件 |

## 3. 核心分享对象

| 对象 | 触发点 | 内容构成 | 主要用途 |
| --- | --- | --- | --- |
| 结算回忆卡片 | 单局结算后 | 游戏名、分数、称号、回忆标签、主题视觉、二维码 | 保存纪念、分享到好友或朋友圈 |
| 挑战邀请卡 | 每周家庭挑战、亲友挑战入口 | 挑战名、目标、游戏入口、活动 ID、二维码或深链 | 邀请亲友一起完成短局 |
| 活动海报 | 节日游园、童年操场月、客厅街机周 | 活动主题、时间、入口二维码、核心视觉 | 运营活动传播 |
| 二维码落地页 | 大屏端结算页、活动页 | 内容 ID、活动 ID、渠道参数、下载或打开入口 | 手机扫码保存、转发或回流开局 |
| 分享结果事件 | 分享动作和落地页回流 | 分享渠道、内容 ID、活动 ID、回流状态 | 数据复盘和渠道评估 |

## 4. 用户流程

### 4.1 移动端流程

```text
完成短局
→ 进入结算页
→ 生成结算回忆卡片
→ 用户选择保存 / 微信好友 / 微信群 / 朋友圈
→ 调起微信或系统分享面板
→ 记录分享触发与结果
→ 好友点击落地页
→ 回到活动页、下载页或同一挑战
```

### 4.2 大屏端流程

```text
完成短局
→ 进入大屏结算页
→ 展示家庭可读的结算结果
→ 展示分享二维码
→ 手机扫码打开结算回忆卡片或活动落地页
→ 手机端保存或微信转发
→ 记录扫码、打开和回流开局
```

大屏端不直接依赖电视端微信登录，也不要求用户在电视上完成微信授权。电视只负责展示二维码和结算内容，分享动作由手机完成。

## 5. 端侧能力差异

| 能力 | 移动端 | 大屏端 |
| --- | --- | --- |
| 分享入口 | 结算页、活动页、挑战页 | 结算页、活动页、家庭挑战页 |
| 分享方式 | 微信好友、微信群、朋友圈、系统分享面板、保存图片 | 二维码扫码、手机保存、手机微信转发 |
| 内容形态 | 图片卡片、链接卡片、活动海报 | 大屏展示图、二维码、活动入口 |
| 权限重点 | 相册保存、微信 SDK、系统分享 | 二维码生成、落地页有效性、扫码回流 |
| 数据重点 | 分享触发、渠道、结果、回流 | 二维码展示、扫码、落地页打开、回流 |

## 6. 数据结构

| 字段 | 说明 |
| --- | --- |
| `share_id` | 单次分享事件 ID |
| `share_type` | `result_card` / `challenge_invite` / `activity_poster` |
| `content_id` | 对应游戏或内容条目 ID |
| `activity_id` | 对应活动 ID，没有活动时为空 |
| `platform` | `mobile` / `tablet` / `tv` |
| `channel` | `wechat_friend` / `wechat_moments` / `wechat_group` / `system_share` / `qr_scan` |
| `landing_url` | 分享或二维码落地页 |
| `created_at` | 分享生成时间 |
| `opened_at` | 落地页打开时间 |
| `conversion_event` | `open_app` / `download` / `start_game` / `join_challenge` |

## 7. 埋点口径

| 事件 | 触发时机 | 关键参数 |
| --- | --- | --- |
| `share_card_generated` | 生成结算回忆卡片 | `share_type`、`content_id`、`platform` |
| `share_action_clicked` | 用户点击保存或分享 | `share_type`、`channel`、`activity_id` |
| `wechat_share_result` | 微信分享完成、取消或失败 | `channel`、`result`、`error_code` |
| `qr_code_shown` | 大屏展示二维码 | `content_id`、`activity_id`、`landing_url` |
| `landing_page_opened` | 落地页被打开 | `share_id`、`channel`、`source` |
| `share_conversion` | 用户完成回流动作 | `conversion_event`、`content_id`、`activity_id` |

## 8. 合规与隐私边界

1. 未成年人相关分享内容不展示真实姓名、精确位置、摄像头画面、家庭成员关系和其他敏感个人信息。
2. 分享文案不得诱导未成年人攀比消费、邀请充值、持续拉人或为了奖励频繁转发。
3. 分享链路不抓取通讯录，不做微信关系链画像，不把群关系用于用户画像。
4. 摄像头画面、实时合影、家庭相册等内容上线前必须单独做隐私复核；MVP 不做此类能力。
5. 分享落地页必须提供清晰的产品来源、打开方式和必要的隐私政策入口。
6. 国内联网版本中，分享回流到游戏、活动或付费入口时，仍需经过实名、防沉迷和未成年人付费限制判断。

## 9. 验收标准

| 阶段 | 验收项 |
| --- | --- |
| MVP | 结算页能稳定生成分享图；移动端可保存图片；大屏端可展示二维码占位；分享相关埋点字段预留完整 |
| 首发 | 微信好友、微信群、朋友圈分享可用；落地页可打开并回流；分享失败、取消、无微信环境都有兜底提示 |
| 成长期 | 家庭挑战和节日活动可按 `activity_id` 追踪分享效果；能区分展示、点击、打开、回流和开局转化 |

## 10. 风险控制

| 风险 | 控制方式 |
| --- | --- |
| 分享变成强制裂变 | 不设置分享解锁玩法、分享领奖励、拉人得分数 |
| 儿童隐私泄露 | 默认只分享抽象成绩和主题视觉，不分享摄像头画面和个人身份信息 |
| 大屏微信登录复杂 | 大屏端只展示二维码，由手机完成微信分享 |
| 落地页失效 | 二维码和链接必须有有效期、降级页和错误提示 |
| 数据过度采集 | 只记录分享效果分析所需字段，不采集通讯录和微信关系链 |
