# MotionX Retro Pack / 复古体感包 风险管理计划

> 本文按照 PMP / PMBOK 风险管理思路编写，用于定义 `MotionX Retro Pack / 复古体感包` 项目的风险管理方法、角色职责、风险分类、评估标准、风险登记册、应对策略、监控机制和升级流程。产品定义见 [MotionX-Retro-Pack-产品定义.md](./MotionX-Retro-Pack-产品定义.md)，立项范围见 [MotionX-Retro-Pack-项目立项说明书.md](./MotionX-Retro-Pack-项目立项说明书.md)，推广运营见 [MotionX-Retro-Pack-推广与运营方案.md](./MotionX-Retro-Pack-推广与运营方案.md)。

## 1. 文件目的

本风险管理计划用于指导项目团队在 MVP、首发、订阅运营和 OEM 渠道扩展阶段，系统识别、分析、应对和监控项目风险。

本计划重点覆盖：

1. 风险管理流程和责任分工。
2. 风险分类结构。
3. 风险概率、影响和优先级评分标准。
4. 风险登记册维护规则，并引用独立的风险登记册。
5. 风险应对策略和触发条件。
6. 风险审查、汇报和升级机制。

## 2. 风险管理目标

项目风险管理目标：

1. 在 MVP 阶段尽早验证产品方向、动作识别、家庭场景和运营包装是否成立。
2. 避免技术能力、版权边界、渠道承诺和运营复杂度失控。
3. 为是否进入首发版本、是否扩展内容、是否开放 OEM 定制提供决策依据。
4. 保证关键风险在进入下一阶段前有明确状态：已关闭、已降低、已接受或已升级。

## 3. 风险管理方法

本项目采用定性风险分析为主、关键指标验证为辅的方式。

管理流程：

1. **规划风险管理**：定义本文件中的流程、角色、标准和模板。
2. **识别风险**：通过产品评审、技术评审、识别测试、版权检查、运营复盘和渠道反馈识别风险。
3. **定性风险分析**：按概率、影响和风险评分评估优先级。
4. **规划风险应对**：为高优先级风险制定规避、减轻、转移、接受或升级策略。
5. **实施风险应对**：由风险负责人推动具体动作。
6. **监督风险**：在阶段 Gate、周会和版本复盘中跟踪风险状态。

```text
MotionX Retro Pack 风险分解结构

   └─ 版本范围变更失控
```

## 6. 概率与影响评分标准

### 6.1 概率评分

| 分值 | 概率等级 | 判断标准 |
| --- | --- | --- |
| 1 | 很低 | 发生可能性低于 10%，仅作为观察项 |
| 2 | 低 | 发生可能性约 10%-30%，需要记录 |
| 3 | 中 | 发生可能性约 30%-50%，需要跟踪 |
| 4 | 高 | 发生可能性约 50%-70%，需要制定应对 |
| 5 | 很高 | 发生可能性高于 70%，必须优先处理 |

### 6.2 影响评分

| 分值 | 影响等级 | 判断标准 |
| --- | --- | --- |
| 1 | 很低 | 对范围、进度、成本、质量或合规影响很小 |
| 2 | 低 | 影响局部模块，可在当前迭代内处理 |
| 3 | 中 | 影响版本质量、用户体验或局部上线计划 |
| 4 | 高 | 影响首发、渠道交付、核心体验或关键指标 |
| 5 | 很高 | 影响项目是否继续、是否能上线或存在重大合规风险 |

### 6.3 风险优先级

风险评分 = 概率分值 × 影响分值。

| 分数 | 优先级 | 处理要求 |
| --- | --- | --- |
| 1-5 | 低 | 记录并观察 |
| 6-12 | 中 | 制定缓解措施并定期跟踪 |
| 15-25 | 高 | 必须指定负责人、触发条件、应对动作和升级路径 |

## 8. 风险应对策略

### 8.1 负面风险应对

| 策略 | 使用场景 | 本项目示例 |
| --- | --- | --- |
| 规避 | 风险不可接受，需改变方案避免发生 | 不做真实老歌、不做真实物理落点、不做精确同步百分比 |
| 减轻 | 降低风险发生概率或影响 | 多人玩法先做轮流和粗粒度同屏 |
| 转移 | 将风险影响转移给第三方或通过合同约束 | 版权素材由授权方提供时需保留授权文件 |
| 接受 | 风险可控，记录后观察 | 低优先级区域偏好差异先在运营数据中观察 |
| 升级 | 超出项目团队权限，需要管理层或法务决策 | 涉及真实 IP 授权、渠道超范围承诺、重大延期 |

### 8.2 正面风险机会

| 机会 | 处理方式 |
| --- | --- |
| 某个主题馆复玩显著高于其他主题馆 | 利用：优先扩展对应主题内容和活动 |
| OEM 对国内主题皮肤反馈强烈 | 增强：沉淀国内主题皮肤包模板 |
| 家庭电视健美操留存好 | 利用：扩展轻健身课程和每周挑战 |
| 街机排行榜带来高复玩 | 增强：强化高分榜、周榜和聚会挑战 |

## 9. 风险监控计划

### 9.1 监控频率

| 阶段 | 频率 | 参与人 |
| --- | --- | --- |
| MVP 制作期 | 每周一次风险检查 | 项目、产品、技术、QA、美术、运营 |
| 内部演示前 | 演示前专项风险评审 | 项目、产品、技术、QA |
| 首发准备期 | 每周一次，关键问题可临时召开 | 项目、产品、技术、运营、渠道、法务 |
| 上线后 2 周 | 每周一次数据复盘和风险复盘 | 产品、运营、技术、渠道 |
| 长线运营期 | 每月一次 | 产品、运营、渠道、数据、技术 |

### 9.2 监控指标

| 指标 | 对应风险 |
| --- | --- |
| `时光体感馆` 入口点击率 | 主题价值是否成立 |
| 样板游戏点击率 | 首发样板排序和封面是否有效 |
| 首局完成率 | 规则、节奏、识别是否过关 |
| 再来一把比例 | 核心乐趣和结算反馈是否成立 |
| 平均游玩时长 | 短局串玩是否自然 |
| 多人参与率 | 家庭场景是否成立 |
| 结算页停留 | 回忆称号和标签是否有效 |
| 校准失败率 | 摄像头识别和入戏式识别是否稳定 |
| 动作识别失败率 | 2D 单目动作原语是否可靠 |
| 活动参与率 | 每周挑战和主题活动是否有效 |
| 渠道素材审核问题数 | 宣传和版权风险是否可控 |

## 10. 阶段 Gate 与退出标准

### 10.1 MVP Gate

进入 MVP 前必须满足：

- 三个样板的玩法目标明确。
- 动作原语落在 2D 单目稳定边界内。
- 不使用真实 IP、真实老歌或影视化造型。
- MVP 数据指标和埋点口径明确。

### 10.2 内部演示 Gate

内部演示通过标准：

- 用户 5 秒内知道要做什么动作。
- 用户 30 秒内理解玩法。
- 三个样板都能完整跑完 1-3 分钟。
- 手机 / 平板上权限、横屏取景、识别、性能和发热无明显阻断。
- 结算页能传达分数、称号和回忆标签。

### 10.3 首发 Gate

进入首发前必须满足：

- 样板游戏首局完成率达标。
- 识别失败率没有明显阻断。
- 宣传素材与真实体验一致。
- 商店图、视频、文案完成版权检查。
- 数据埋点可以区分入口、完成、复玩、识别失败和主动退出。

### 10.4 扩展 Gate

扩展到 10+ 内容或启用《童年的一天》结构前必须满足：

- 首批主题馆有稳定点击和复玩。
- 至少一个家庭挑战活动表现良好。
- 新内容不是简单换皮凑数。
- 国内主题皮肤有明确用户记忆和渠道依据。

## 11. 风险升级机制

风险需要升级的条件：

1. 风险评分达到 15 分及以上，且当前团队无法在本阶段关闭。
2. 涉及版权、真实 IP、真实音乐、商标或地区合规。
3. 渠道或 OEM 提出超出当前版本边界的承诺。
4. MVP 样板无法按 Gate 标准完成。
5. 宣传素材与真实产品能力不一致。

升级路径：

```text
风险负责人
→ 项目负责人
→ 产品 / 技术 / 运营 / 法务专项评审
→ 项目决策会
→ 调整范围、延期、降级、取消或进入后续版本池
```

## 12. 风险登记册维护规则

风险登记册由项目负责人维护。

每条风险至少包含：

- 风险 ID。
- 风险描述。
- 风险分类。
- 概率。
- 影响。
- 风险评分。
- 优先级。
- 风险负责人。
- 应对策略。
- 触发条件。
- 当前状态。
- 下次检查时间。

风险状态：

| 状态 | 含义 |
| --- | --- |
| 新增 | 刚识别，尚未完成评估 |
| 评估中 | 正在确认概率、影响和负责人 |
| 应对中 | 已制定动作，正在执行 |
| 监控中 | 风险已降低，但仍需观察 |
| 已关闭 | 风险已消除或不再影响当前阶段 |
| 已接受 | 团队明确接受该风险并记录原因 |
| 已升级 | 超出当前团队权限，已提交上级或专项评审 |

## 13. 变更控制

以下变更必须触发风险复评：

1. MVP 样板数量增加。
2. 新增真实 IP、音乐、角色或影视化表达。
3. 新增需要前后纵深、真实落点、精确同步率的玩法。
4. 新增 OEM 深度定制需求。
5. 新增重运营系统，例如等级、装备、货币、复杂任务。
6. 宣传素材出现尚未实现的产品能力。
7. 手机 / 平板权限、横屏取景、识别、性能或发热结果低于预期。
8. 国内联网版本弱化或后置账号实名、防沉迷、未成年人限制、隐私提示或付费拦截。

变更处理顺序：

```text
提出变更
→ 评估影响范围
→ 更新风险登记册
→ 决定接受、延期、降级或拒绝
→ 更新版本范围和验证标准
```

## 14. 风险汇报模板

每次风险复盘建议使用以下格式：

| 字段 | 内容 |
| --- | --- |
| 本期新增风险 | 新识别的风险和来源 |
| 高优先级风险 | 评分 15 分及以上的风险 |
| 风险状态变化 | 新增、降低、关闭、升级 |
| 需要决策事项 | 需要项目决策会处理的问题 |
| 下期重点 | 下次检查前必须完成的应对动作 |

## 15. 一句话总结

`MotionX Retro Pack / 复古体感包` 的核心风险管理原则是：先用三个样板证明产品价值和识别稳定，再扩大国内内容和渠道；所有复古表达必须原创且适配国内家庭语境；所有推广承诺必须落在真实可运行的 2D 单目体感能力内。海外市场、海外皮肤和海外营销话术暂不进入当前风险验收范围。
