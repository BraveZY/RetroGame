# 单个复古体感游戏标准流程参考

> 本文是 `MotionX Retro Pack` 单个游戏包装流程的细节参考。主方案见 [MotionX-Retro-Pack-产品定义.md](./项目管理计划/MotionX-Retro-Pack-产品定义.md)。开发排期和优先级以主方案为准；本文用于策划、美术、音效、UI 在设计单个游戏时查细节和例子。

## 0. 使用边界

每个复古体感游戏都应按“回忆开场 → 入戏识别 → 角色关系 → 核心玩法 → 欢乐反馈 → 结算界面 → 奖励卡片/纪念表达”的顺序设计。

但首发验证期不要把所有细节都做成重系统：

- P0：回忆开场、入戏式识别、亲子/多人角色、核心玩法。
- P1：欢乐反馈、结算界面。
- P2：纪念照片或实时合影管线。

<a id="memory-intro"></a>

## 1. 回忆开场，10-20 秒

目标是在进入玩法前，用声音、画面和一句话把用户带入场景。它不是剧情播片，而是低成本的情绪入口。

可用素材：

- 下课铃。
- 电玩城投币声。
- 老电视开机声。
- 操场广播。
- VHS 录像带插入声。
- 街机灯亮、计分牌启动、倒计时。

示例：

- 操场木头人：下课铃响，操场广播提示“集合”。
- 电玩城投篮机：投币声后，机器灯亮，倒计时牌跳动。
- 家庭电视健美操：电视雪花闪一下，VHS 标题卡出现。

<a id="themed-recognition"></a>

## 2. 入戏式识别

不要把识别过程说成“正在校准”。识别也是体验的一部分，应包装成场景行为。

可用话术：

- “站到队伍里。”
- “准备上场。”
- “投币成功。”
- “操场集合。”
- “请站到起跑线。”
- “站到电视机前，录像带马上开始。”
- “站到你的颜色区。”

设计原则：

- 让用户知道自己该站哪里。
- 让识别等待时间有场景意义。
- 不要出现过多技术词，例如骨骼、识别、校准、算法。

<a id="family-roles"></a>

## 3. 父母与孩子进入角色

复古体感包的价值不是单人高分，而是家庭关系被带进游戏。每个游戏都应考虑父母、孩子、旁观者分别能做什么。

可支持角色：

- 父母示范。
- 孩子挑战。
- 亲子组队。
- 大人队 vs 孩子队。
- 轮流上场。
- 同屏竞速。
- 粗粒度家庭同步感。

注意：首发不要做精确家庭同步率。2D 多人会受遮挡和站位影响，精确百分比不稳定。可改成三档鼓励性结果：

- 完美默契。
- 还不错。
- 各跳各的。

<a id="core-gameplay"></a>

## 4. 核心体感玩法

核心玩法应复用现有动作识别和主方案中的动作原语，避免为复古包新开一套重判定。

可复用动作：

- 挥拍。
- 出拳。
- 跳跃。
- 跑停。
- 抬膝。
- 投掷 / 摆臂。
- 左右闪避。
- 深蹲。
- 举手。
- 拍手。
- 手伸到屏幕指定区域。

设计原则：

- 一局 1-3 分钟。
- 5 秒看懂。
- 30 秒学会。
- 失败也能让旁观者看懂发生了什么。
- 不做 2D 单目不稳定的真实落点、前后纵深、精细手腕手指。

<a id="fun-feedback"></a>

## 5. 欢乐反馈

错了不要严肃失败，而是轻松反馈。首发只需要一组通用安全文案，不要一开始做海量动作分支。

可用文案方向：

- “这位同学左右手打架了。”
- “爸爸当年可能是体育委员。”
- “后排同学动作很有想法。”
- “全家同步感正在回升。”
- “刚才那一下很像放学铃响之后的速度。”
- “这一轮动作很有年代感。”
- “差一点就进高分榜了。”

文案原则：

- 轻松，不羞辱用户。
- 能被孩子和家长共同接受。
- 多语言本地化后仍然不尴尬。
- 不绑定过细动作结果，避免内容维护成本过高。

<a id="memory-settlement"></a>

## 6. 结算界面

结算界面首先是本局结果页，必须清楚显示分数、评价和下一步操作。童年元素只作为视觉和文案包装，不把解锁收藏、贴纸、照片等奖励内容混在结算主体里。

可展示内容：

- 分数。
- 本局称号。
- 回忆标签。
- 今日最佳动作。
- 粗粒度同步感。
- 父母童年指数。
- 孩子体验完成度。

首发建议保留：

- 分数。
- 本局称号。
- 回忆标签。
- 同步感三档。

可以推迟：

- 父母童年指数。
- 孩子体验完成度。
- 复杂动作复盘。
- 精确同步百分比。

示例称号：

- “课间操场冠军。”
- “电玩城今日高手。”
- “家庭电视健身队。”
- “最稳木头人。”
- “放学后投篮王。”

<a id="souvenir-expression"></a>

## 7. 奖励卡片 / 纪念表达

奖励卡片负责解锁、收藏和可分享表达，应与结算界面分开。纪念照片是很强的情绪收尾，但实时合影、换装、背景合成会形成独立图像管线。验证期不要把它放进 P0。

可作为 P2 的完整方向：

- 复古校服合影。
- 电玩城冠军照。
- VHS 健身录像封面。
- 校运会家庭队合影。
- 课间十分钟纪念照。

验证期替代方案：

- 静态奖励卡片。
- 称号卡片。
- 贴纸、徽章、照片等收藏项。
- 本局高光动作名称。
- 结算后可截图分享的奖励页。

<a id="round-template"></a>

## 8. 单局流程模板

```text
回忆开场 10-20 秒
→ 入戏式识别 5-10 秒
→ 角色分配 / 队伍确认
→ 核心玩法 1-3 分钟
→ 欢乐反馈穿插
→ 结算界面 10-20 秒
→ 奖励卡片 / 后续 P2 纪念照片
```

<a id="minimum-version"></a>

## 9. 最小可开发版本

如果一个游戏要进入两周演示版本，最低只要求：

1. 一个 10-20 秒回忆开场。
2. 一套入戏式识别话术。
3. 一个稳定的 2D 动作原语组合。
4. 一组通用欢乐反馈。
5. 一个带童年元素的结算界面。
6. 一个本局称号和一个回忆标签。
7. 可选：一个独立奖励卡片，用于贴纸、徽章或收藏项解锁。

其他内容等验证用户确实愿意为“回忆包装”多玩一次后再加。
