# 时光派对大屏端字符游戏界面草图

> 本文是大屏端 / 跨端参考的低保真界面补充，用字符草图表达电视远距离可读的核心界面结构、信息层级和单局流程。当前手机 / 平板 MVP 原型 authority 见 [移动端ASCII原型草图](./MotionX-Retro-Pack-移动端ASCII原型草图.md)。本文不是最终美术稿，也不定义视觉资产规格。

## 1. 使用目的

- 快速确认 `时光派对` 的首页主题入口、主题页玩法切换、识别、游戏中和结算流程。
- 帮助产品、设计、工程在没有正式界面图之前对齐信息层级。
- 约束首版体验优先做到远距离可读、五秒看懂、一到三分钟短局闭环。
- 界面不直接用“复古”“怀旧”“八零九零”等词强调年代感；年代感主要通过画面、音乐、音效和交互符号表达。
- 本文只作为大屏端和跨端信息层级参考；移动端页面、触控、权限、横屏取景和保存分享以移动端原型为准。

## 2. 页面层级与主流程

主流程：

```
游戏启动
  -> 健康游戏忠告过渡页
  -> 登录页面
  -> 首页
  -> 童年操场主题页
      -> 开始挑战
          -> 入戏式识别 / 准备页
              -> 游戏中
                  -> 结算界面
                      -> 奖励卡片
```

- 健康游戏忠告过渡页承担进入游戏前的行业自律提示，停留后进入登录页。
- 登录页面承担首次进入、账号选择、协议确认、适龄提示和出版 / 备案 / 协议信息展示。
- 首页承担主题选择。
- 点击首页右上角 `[头像]` 进入 `我的界面`，查看家庭小队、头像、最近奖励、主题收藏和家庭奖励。
- 点击首页右上角 `[帮助]` 或准备页右上角 `[帮助]` 进入独立 `帮助页面`，只展示站位自查、常见问题和家长放心说明。
- 点击首页或我的界面右上角 `[⚙]` 进入 `设置界面`，查看家长说明、内容限制、隐私和基础体验设置。
- 主题页承担主题介绍、当前主玩法展示和玩法切换。
- `开始挑战` 直接进入准备页。
- 主题页中的玩法卡片只切换当前主玩法，不跳转到新页面。

|                                                                            |
|                                                                            |
|                         即将进入登录页面                                    |

```

交互说明：

- 游戏启动后先展示本页，再进入登录页。
- 本页只承担健康游戏忠告，不承载账号、活动、付费、摄像头、奖励或玩法入口。
- 自动停留约 1.5 秒，也可点击继续，避免启动节奏拖慢。
- 文字需要高对比、居中、远距离可读；背景可使用模糊的童年场景或启动图，但不能影响忠告文本阅读。

设计意图：

- 参考常见移动游戏启动链路，在正式登录前先完成健康游戏忠告露出。
- 过渡页不做“玩法介绍”或“产品卖点”，避免削弱健康提示的正式性。
- 视觉可延续 `时光派对` 的明亮、亲子、轻怀旧气质，但文字层级应优先于装饰。

交互说明：

- 首次进入必须展示协议确认，未勾选时点击 `继续进入`、`手机号登录` 或 `游客体验` 都先提示阅读协议。
- `继续进入` 用于已登录或本机已有家庭资料的回流用户，直接进入首页当前推荐主题。
- `手机号登录` 用于保存收藏、奖励和家庭进度；登录流程不在本页展开。
- `游客体验` 允许先进入首页和 MVP 样板体验，但涉及分享、购买、长期收藏同步时再提示登录或家长确认。
- `4+ 适龄提示` 展示适龄提示入口；协议文字展示用户服务协议、隐私政策、儿童隐私保护协议和第三方信息共享清单。
- 登录页不展示摄像头、识别、校准、骨骼、算法等技术词，也不展示复杂账号后台。

设计意图：

- 登录页是高品质游戏开场，不是普通账号表单；第一眼要建立 `时光派对` 的家庭、童年、体感和轻怀旧气质。
- 主视觉用效果图资产延续首页记忆桌面方向，不把道具说明写成页面可见文案。
- 主动作只有一个：`继续进入`；手机号登录、游客体验、协议与家长说明都作为辅助入口，避免首屏选择压力过大。
- 底部合规信息要清楚可见，但不能像后台表格压住整个游戏气质。
- 协议确认、适龄提示、备案 / 出版信息要常驻登录页底部，形成用户进入前的基础信任信息。
- 所有登录与协议相关文案都面向家长和家庭信任，不使用儿童压力文案，不诱导未成年人付费或分享。

|          |                铃声响了，站到跑道边                  |           |

|          |                                                      |           |

|                                                                            |
|        今日活力 68       最新称号 课间小冠军       本周挑战 3/5             |

```

设计意图：

- 首页采用“现代家庭游戏大厅 + 当前主题主舞台”的结构，第一眼先读出当前主题和主按钮。
- 顶部只保留头像、帮助和设置等轻量入口，不重复品牌标题，不把主题入口做成工具栏或目录页。
- 左右切换控件改为贴近主舞台边缘的游戏化箭头，不显示 `上一题 / 下一题` 这类表单感文字。
- 主舞台不展示 `背景：`、`锚点：` 等设计说明；跑道线、粉笔格、下课铃应作为画面元素出现。
- 主题切换时，只同步主舞台标题、氛围、3 个主记忆锚点、CTA 文案和底部位置点。
- 首页不展示玩法列表、摄像头、玩家数、识别或校准状态；这些信息应在主题页或准备页出现。
- 活力、称号和本周挑战作为底部弱 HUD，不能抢走“当前主题 + 进入操场”的主层级。

## 6. 入戏式识别：操场木头人

```
+----------------------------------------------------------------------------+
| < 操场木头人                                             [?]                |
+----------------------------------------------------------------------------+
|                                                                            |
|                     叮铃铃，下课了                                         |
|                  站到粉笔线后，准备开跑                                    |
|                                                                            |
|              +--------------------------------------------+                |
|              |                                            |                |
|              |              全家站位区                    |                |
|              |                                            |                |
|              |        A 已上场      B 已上场      C 已上场 |                |
|              |                                            |                |
|              +--------------------------------------------+                |
|                                                                            |
|          A 小队长 ✓          B 爸爸 ✓          C 妈妈 ✓                    |
|                                                                            |
|                              3                                             |
|                         [ 准备开始 ]                                       |
+----------------------------------------------------------------------------+
```

设计意图：

- 本页是“上场舞台”，不是摄像头监控页；中间应是一块清楚的全家站位区。
- 用户可见文案避免“摄像头、识别、骨骼、算法、校准”等技术词，改用 `已上场`、`粉笔线`、`准备开跑`。
- 玩家状态用头像牌 / 站位牌表达，底部只确认谁已上场，不展示三张取景框占满主视觉。
- 倒计时是本页最强动作信号；全员就绪后自动开始，也可保留一个明确的 `准备开始` 主按钮。
- 帮助入口只放右上角，解决站位问题时才进入帮助页，不抢主流程。

设计意图：

- 成功 / 失败反馈贴近玩家进度显示，避免在画面中心叠太多文字。
- 终点线放在底部作为场景目标，强化“朝终点冲”的动作理由。
- 失败反馈保持轻松，例如 `动了，少十分`、`下次试试雕像姿势`，不使用羞辱性文案。

- 核心动作仍然是二维稳定动作原语：手到区域、摆臂。
- 下个奖励提示改为短句，服务当前节奏，不做复杂任务链。

- `协议与说明` 是常驻合规入口，至少包含隐私政策、用户服务协议、儿童隐私保护协议、第三方 SDK 说明和权限说明。

- 设置项默认即时生效；需要系统授权、外链或购买相关确认时，进入对应子页或系统弹窗处理。
- `体验设置` 只调体验参数，不提供会影响玩法公平性的能力加成。
- 固定规则不可关闭：儿童奖励不可购买，贴纸、徽章、称号和奖励卡片只能通过游玩获得。

设计意图：

- `设置界面` 是家庭保护和基础体验配置入口，不是开发者配置页、账号后台或运营活动入口。
- 依据家长控制与内容限制设计，首版采用“少开关、强默认、关键处确认”的方式。
- 采用顶级产品常见的设置中心结构：左侧分组、右侧详情、设置即时生效与必要确认。
- 设置项按用户心智组织，而不是按技术模块堆叠；家长先看到保护结果，再决定是否调整细项。
- 页面必须保护家庭信任：不诱导儿童付费，不把分享作为领奖励或解锁玩法的前置条件。
- 摄像头相关文案要说清用途和边界，但不在普通用户界面暴露骨骼、算法、模型等技术词。
- 设置项以功能模块分组，便于后续扩展实名 / 防沉迷、系统购买限制、Game Pass 活动限制、账号安全和家长 PIN。

## 13. PixiJS 原型样式抽层规则

| 类型 | 管理位置 | 使用规则 |
| --- | --- | --- |
| 颜色 | `web-prototype/src/uiStyle.ts` 的 `ui.color`，并复用 `domain.ts` 的 `palette` | 页面不直接新增散落色值；新增颜色先命名为语义色 |
| 字体 / 字号 / 字重 | `ui.font.family / size / weight / lineHeight` | 页面标题、分组标题、正文、说明、按钮文字按 token 取值 |
| 文本语义样式 | `ui.textStyle` + `styledLabel()` | 优先用 `headerTitle / pageTitle / panelTitle / itemTitle / itemDesc / hudText / legalText / buttonText` |
| 间距 / 圆角 / 描边 | `ui.space / radius / stroke` | 面板、按钮、行高、控件间隔使用统一尺寸 |
| 画布布局 | `ui.layout` | 通用 header、设置页双栏、行高和面板尺寸集中维护 |
| 控件尺寸 | `ui.component` | 按钮、开关、滑杆、分段选择、状态胶囊统一尺寸 |
| 按钮层级 | `primaryButton / secondaryButton / themeButton / ghostButton / smallButton / dangerButton` | 页面不直接用颜色表达按钮层级；主题主动作使用 `themeButton` |
| 设置项类型 | `SettingsGroup.items[].control` | 不靠文字推断控件；显式声明 `switch / lockedSwitch / slider / segmented / link / status / action` |

样式原则：

- 保持明亮、可读、家庭友好，避免暗色后台感和过度企业 App 感。
- 设置页控件必须符合用户心智：音量是滑杆，字号是分段选择，阅读协议是查看按钮，只读信息是状态胶囊。
- 不可关闭的家庭保护规则用锁定态表达，不伪装成可点击开关。
- 主按钮、次按钮、主题按钮要使用明确组件，避免每个页面自行传色导致层级漂移。
- 允许轻怀旧色彩和纸张质感，但不能牺牲横版手机上的可读性和触达面积。

| 首页 | 展示 `时光派对` 品牌、回忆目录和当前主题物件特写 | 用户能一眼理解这是主题入口页 |
| 我的界面 | 承接家庭小队、头像、最近奖励、我的收藏、主题进度和家庭奖励 | 用户知道奖励来自游玩，并能查看收藏和家庭进度 |
| 设置界面 | 展示家长说明、内容限制、隐私、声音画面和休息提醒 | 家长能理解保护边界，且不会被复杂设置打断 |
| 童年操场主题页 | 展示操场场景、当前主玩法和其他操场玩法 | 用户能直接开始样板玩法，路径不重复 |
| 玩法切换 | 在主题页内切换当前主玩法 | 切换玩法不跳转新页面，预告玩法不会误进入准备页 |
| 入戏式识别 | 用场景话术包装识别准备 | 用户不感到是在处理技术校准 |
| 游戏中状态栏 | 支撑一到三分钟短局 | 远距离可读，旁观者能看懂 |
| 结算界面 | 呈现本局结果并带童年视觉包装 | 分数、称号、标签、同步感和下一步操作清楚 |
| 奖励卡片 | 承接解锁、收藏和分享 | 与结算界面分开，不遮挡本局结果 |

## 15. 后续可视化方向

- 登录页面：做成高品质游戏开场，延续记忆桌面视觉，用主按钮快速进入，协议与家长说明作为清晰辅助入口。
- 首页：采用记忆桌面目录版，用回忆目录和当前物件特写承载主题入口，避免回到三张卡片大厅。
- 我的界面：做成家庭小队档案和游戏资产入口，以头像、最近收获、贴纸、徽章、称号、主题进度和家庭奖励为主。
- 设置界面：做成清楚的功能模块页，重点是家长说明、内容限制、隐私、摄像头说明、声音画面和休息提醒。
- 童年操场主题页：保留场景沉浸感，但只承接主题介绍、玩法切换和开始挑战。
- 游戏中状态栏：只保留三到五个核心信息区，避免体感游戏中读不清。
- 结算界面：先保证本局结果清楚，再加入童年视觉元素。
- 奖励卡片：静态卡先行，后续再扩展合影、分享图、活动任务。
