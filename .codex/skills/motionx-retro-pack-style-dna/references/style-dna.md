# MotionX Retro Pack / 游戏 DNA 与风格统一规范

> 本文用于统一 `MotionX Retro Pack / 复古体感包` 的美术、UI、音效、文案、动效和单局包装风格。它不是功能范围文档，也不是单个游戏 GDD；它回答“所有内容看起来、听起来、玩起来为什么像同一个产品”。

## 1. 一句话 DNA

> 让爸妈带孩子，在今天的客厅里，重新玩一次自己小时候的课间、街机、电视健身和游园挑战。

这款游戏的 DNA 不是“复古滤镜”，而是：

```text
家庭共同参与
+ 童年场景记忆
+ 1-3 分钟短局体感
+ 明亮清晰的现代 UI
+ 轻怀旧元素点题
+ 原创安全表达
= 时光体感馆 / Time Play
```

## 2. 核心风格公式

| 构成 | 权重 | 作用 | 设计判断 |
| --- | ---: | --- | --- |
| 家庭体感体验 | 40% | 决定用户为什么站起来、怎么动、怎么一起玩 | 孩子不懂怀旧也能玩 |
| 具体童年场景 | 30% | 决定画面、音效、文案和反馈来自哪里 | 看 5 秒知道在哪里 |
| 轻怀旧识别点 | 20% | 让父母产生“这是我小时候”的入口情绪 | 点到为止，不堆旧物 |
| 现代可读 UI | 10% | 保证电视 / 平板 / 手机都清楚 | 3 米外能看清关键反馈 |

设计比例建议：

```text
主题体验 70%
怀旧元素 30%
```

怀旧元素只负责“唤起”，主题体验负责“可玩”。

## 3. 五个不可丢的基因

| DNA | 含义 | 落到设计上 |
| --- | --- | --- |
| 亲子发起 | 父母有理由点开，孩子有理由继续玩 | 入口、开场和结算都要让家庭关系成立 |
| 场景先行 | 每个游戏先回答“我在哪里” | 操场、老电视、街机、游园摊位必须带出动作理由 |
| 短局爽快 | 不做长剧情和重系统 | 5 秒看懂，30 秒学会，1-3 分钟结束 |
| 轻松反馈 | 失败也能笑一下 | 不羞辱用户，不做严肃运动考核 |
| 原创复古 | 要复古感，不碰真实 IP | 音乐、角色、造型、台词、图形全部原创抽象化 |

## 4. 风格关键词

| 方向 | 应该像 | 不应该像 |
| --- | --- | --- |
| 情绪 | 温暖、热闹、亲切、轻松、可分享 | 昏暗、破旧、压抑、成人怀旧展 |
| 画面 | 明亮的童年舞台、清楚的动作空间 | 泛黄旧照片、重噪点、低对比拼贴 |
| UI | 现代清晰 + 轻复古装饰 | 纯像素、纯 VHS、复杂扫描线 |
| 玩法 | 场景里的身体动作 | 抽象运动测试、设备校准流程 |
| 文案 | 像游戏现场有人在喊你上场 | 像产品介绍、技术提示、怀旧讲座 |
| 音效 | 下课铃、投币、电视雪花、广播、鼓点的原创变体 | 真实老歌、影视音乐、可识别街机音源 |

### 4.1 90 后生活记忆场景 DNA

当需要做主题馆头图、小游戏封面、奖励卡、入戏开场、登录 / 入口大图或 AI 生图参考时，可采用下面的视觉子风格：

```text
明亮童年生活场景
+ 轻怀旧物件锚点
+ 平面图形化 2D 场景表现
+ 电视综艺式高辨识标题
+ 现代家庭体感游戏 UI 骨架
= MotionX 的 90 后生活记忆家庭体感方向
```

| 维度 | DNA 描述 |
| --- | --- |
| 核心情绪 | 温暖、轻快、怀旧、课间感、暑假感，像家庭共同经历过的生活片段 |
| 场景类型 | 家庭客厅、校园操场、社区空地、夏日树荫、家人和朋友一起互动 |
| 美术气质 | 平面图形化 2D，构图利落、色块清楚、线条干净；以层级与节奏而非立体材质建立生活感，不做绘本或低幼卡通 |
| 色彩 | 暖黄色、草绿、浅蓝、米白为主，整体明亮低饱和，带一点夏日阳光感 |
| 记忆锚点 | 老电视、收音机、奖状、军绿色书包、红领巾、铁环、弹珠、木椅、田埂、操场白线 |
| 人物 | 全龄家庭与朋友群像，比例自然、表情有活力；以奔跑、蹲下、围观、跟练等集体动作传达参与感，不用幼态大头身 |
| 字体 / 标题 | 高对比、醒目的节目 / 游戏标题感；避免儿童节目式粗黑描边与过度卖萌字形 |
| 产品补足 | 必须叠加现代、清晰、可操作的游戏 UI 骨架，例如主题卡、开始按钮、人数 / 时长 / 强度、倒计时、分数、体感站位提示 |
| 适用方向 | 童年操场、儿时课间游戏、90 后童年回忆主题、小游戏封面、主题详情头图、奖励卡插画、入戏开场 |
| 风险 | 只做场景插画会偏怀旧内容封面；过度圆润、玩具化或萌系角色会滑向低幼，不够像现代家庭体感游戏产品 |

一句话定义：

> 明亮干净的 90 后生活记忆场景，用具体游戏和老物件唤起记忆，并以现代家庭体感游戏 UI 落地；它应全龄亲和，而不是儿童绘本或低幼卡通。

| 场景 | 明亮操场 / 客厅 / 电视舞台，背景服务动作空间 | 完整写实校园实景、怀旧物件展陈、纯绘本封面 |
| 情绪 | 热闹、亲子、干净、可玩，父母有回忆触发 | 旧照片、脏旧学校、成人怀旧展、过度剧情化 |
| 文字 | 可生成少量占位式大字；正式文案后期由 UI / Unity 重做 | 大段 AI 乱码、真实校名、真实品牌或可识别标语 |

## 5. 统一视觉 DNA

### 5.1 色彩

| 类型 | 建议 |
| --- | --- |
| 主色气质 | 明亮、温暖、有童年感，但不做大面积土黄旧化 |
| 可用色感 | 操场红、粉笔白、广播蓝、奖状红、街机亮色、电视节目彩条感 |
| 对比要求 | 关键分数、倒计时、站位区、动作提示必须高对比 |
| 避免 | 大面积暗黄、脏绿、灰褐、低亮度噪点、怀旧滤镜覆盖全屏 |

### 5.2 形状与图形语言

| 元素 | 统一方向 |
| --- | --- |
| UI 面板 | 简洁平面块面，边缘可带轻微复古标签 / 贴纸 / 黑板报感；不用玻璃、金属或细腻质感渲染 |
| 按钮 | 大尺寸、明确状态、适合电视远距离和触屏点击 |
| 图标 | 物件抽象化的平面图标：口哨、铃铛、奖章、投币、电视、队旗、篮球框 |
| 背景 | 是可玩的场景，不是静态怀旧陈列 |
| 角色 | 亲和、家庭化、原创，不追求写实明星或影视角色 |

### 5.3 画面层级

```text
第一层：动作区域 / 目标物 / 倒计时
第二层：分数 / 当前目标 / 玩家状态
第三层：场景氛围 / 怀旧装饰
第四层：非关键贴纸 / 纹理 / 背景小物
```

规则：怀旧装饰永远不能压过动作提示。

### 5.4 游戏中 HUD 占屏与焦点

游戏中 HUD 的“大”指远距离可读，不是全屏铺满卡片。默认按下列约束设计或生成概念图；具体实现可根据屏幕安全区微调。

| 项目 | 默认约束 |
| --- | --- |
| 动作区 | 至少保留画面 55% 为无阻挡的中央 / 前景动作区；站位、目标物和轨迹不得被常驻面板遮挡 |
| 顶部 HUD | 总高度不超过画面约 15%；只放分数、倒计时和紧凑目标摘要 |
| 底部 HUD | 总高度不超过画面约 12%；只在“动作提示”与“玩家状态”中突出一项，另一项缩为角标或按需出现 |
| 信息焦点 | 同一时刻只有一个主视觉反馈；连击、成功、警告为短暂弹出，不与当前动作提示并列常驻抢焦点 |
| 信息去重 | 当前目标不得同时以大面板出现在顶部、中央和底部；进度、流程和文案只保留一个主入口 |
| 道具与怀旧 | 道具栏缩为角落图标，怀旧细节只在边缘；不能占据中央动作路径 |

## 6. UI 统一 DNA

| UI 场景 | 统一规则 | 示例 |
| --- | --- | --- |
| 主题入口 | 用主题馆组织，不平铺大量小游戏图标 | 童年操场、客厅街机、家庭电视健身 |
| 游戏卡片 | 一眼说明场景、人数、时长、强度 | `1-4 人`、`90 秒`、`中高强度` |
| 入戏识别 | 不说技术词，用场景语言 | “准备上场”“站到队伍里”“投币成功” |
| 游戏中 HUD | 少字、关键数字清楚、单一反馈焦点、至少 55% 动作区 | 倒计时、分数、短暂连击、当前动作 |
| 结算 | 分数清楚，记忆标签点题 | “课间小冠军”“全家节拍对上了” |
| 奖励 | 和结算分离，做轻收藏 | 奖章、贴纸、称号卡、节目封面 |

## 7. 文案统一 DNA

### 7.1 推荐语气

| 场景 | 语气 |
| --- | --- |
| 开场 | 像广播、摊主、街机机器、电视节目主持人在招呼玩家 |
| 规则 | 短句、动作明确、少解释 |
| 反馈 | 轻松调侃，但不嘲笑 |
| 结算 | 像给家庭留下一个小称号 |

### 7.2 推荐句式

| 类型 | 示例 |
| --- | --- |
| 场景 + 动作 | 下课了，站到队伍里。 |
| 身份 + 目标 | 今天轮到你挑战高分。 |
| 规则包装 | 老师看过来了，别动。 |
| 家庭协作 | 全家一起跟上节拍。 |
| 结算记忆 | 称号：课间小冠军。 |

### 7.3 禁止句式

| 禁止 | 原因 |
| --- | --- |
| 正在识别人体骨骼 | 技术感外露 |
| 请完成校准流程 | 破坏入戏 |
| 这是 80/90 后经典回忆 | 像说明书，不像游戏 |
| 观看剧情后开始 | 暗示等待成本高 |
| 你动作太差了 | 羞辱用户，不适合亲子 |

## 8. 音频统一 DNA

| 类型 | 方向 | 边界 |
| --- | --- | --- |
| 记忆触发音 | 下课铃、口哨、广播、投币、电视雪花、节目开场 | 必须原创或抽象化 |
| 游戏节奏 | 明确节拍，帮助身体跟随 | 不用真实老歌，不模仿名曲旋律 |
| 成功反馈 | 灯牌亮、掌声、奖券、广播表扬、计分跳动 | 不使用可识别 IP 音效 |
| 失败反馈 | 轻松短促，不刺耳 | 不做惩罚性噪音 |
| 结算音乐 | 温暖、有完成感 | 不煽情，不像长剧情结尾 |

## 9. 动效统一 DNA

| 动效 | 规则 |
| --- | --- |
| 入场 | 像场景启动：灯亮、广播响、电视开机、投币成功 |
| 倒计时 | 清楚、有节拍，动作前 3 秒必须明确 |
| 命中 | 目标物、分数、声音三者同步 |
| 失败 | 轻量弹回 / 摇晃 / 提示，不挡住下一次动作 |
| 结算 | 先出分数，再出称号和回忆标签 |

动效不能为了怀旧做过多闪烁、扫描线或故障效果，尤其不能影响儿童用户和远距离可读性。

## 10. 三个首批主题馆的 DNA 差异

| 主题馆 | 场景 DNA | 视觉关键词 | 音频关键词 | 文案关键词 | 代表动作 |
| --- | --- | --- | --- | --- | --- |
| 童年操场 | 课间、队伍、老师视线、放学后 | 跑道、粉笔线、广播、队旗、教学楼 | 下课铃、口哨、操场广播 | 站到队伍里、老师看过来了、课间开始 | 跑停、冻结、跳跃、侧移 |
| 客厅街机 | 投币、灯牌、高分榜、围观 | 分数板、灯箱、按钮、投篮框、挑战区 | 投币、机器启动、计分跳动 | 投币成功、挑战启动、看看谁能上榜 | 挥臂、伸手、出拳、反应 |
| 家庭电视健身 | 老电视、节目、节拍、全家跟做 | 电视框、节目标题、动作预览、彩条 | 电视雪花、原创节拍、节目口令 | 站到电视前、跟上节拍、全家一起 | 抬膝、挥臂、深蹲、拍手 |

## 11. 单个游戏统一模板

每个游戏至少填写下面 10 项，避免风格走散。

| 项目 | 填写要求 |
| --- | --- |
| 游戏名 | 中文名 + 可选英文名 |
| 所属主题馆 | 童年操场 / 客厅街机 / 家庭电视健身等 |
| 场景一句话 | 用户在哪里 |
| 玩家身份 | 用户是谁 |
| 动作理由 | 为什么要做这些动作 |
| 核心动作原语 | 必须落在 2D 单目稳定动作内 |
| 记忆触发音 | 一个最强音频锚点 |
| 关键视觉锚点 | 一个最强画面锚点 |
| 反馈语言 | 成功 / 失败 / 连击怎么说 |
| 结算记忆 | 称号 + 回忆标签 |

示例：

| 项目 | 操场木头人 |
| --- | --- |
| 所属主题馆 | 童年操场 |
| 场景一句话 | 下课后操场上的跑停游戏 |
| 玩家身份 | 准备冲线又要随时停住的同学 |
| 动作理由 | 跑得快，也要在老师回头时停稳 |
| 核心动作原语 | `RunStop` + `FreezeStill` + `SimultaneousRace` |
| 记忆触发音 | 下课铃 + 口哨 |
| 关键视觉锚点 | 起跑线 + 老师视线 |
| 反馈语言 | 老师看过来了，别动 |
| 结算记忆 | 称号：最稳木头人；标签：课间冲刺队 |

## 12. 设计红线

| 红线 | 说明 |
| --- | --- |
| 不做纯怀旧滤镜 | 泛黄、噪点、像素、扫描线不能替代玩法 |
| 不做真实 IP 复刻 | 老歌、影视、街机、动画、明星形象都不能碰 |
| 不做技术语言外露 | 校准、骨骼、算法、识别尽量不出现在用户文案里 |
| 不做儿童看不懂的怀旧展 | 怀旧元素必须服务玩法理解 |
| 不做低幼儿童包装 | 不用儿童绘本画风、幼态大头身、玩具化吉祥物、过度卖萌图标或儿童节目式标题作为默认表达 |
| 不做暗、脏、旧 | 复古要明亮清楚，孩子愿意进入 |
| 不做长剧情 | 开场 10-20 秒，快速进入短局 |
| 不做重惩罚 | 家庭游戏失败也要轻松 |
| 不做 2D 不稳定动作 | 真实落点、前后纵深、精细手指不能做核心体验 |

## 13. 一页验收清单

| 问题 | 通过标准 |
| --- | --- |
| 5 秒内知道在哪里吗？ | 能说出操场、街机、电视健身或游园等具体场景 |
| 30 秒内知道怎么玩吗？ | 动作目标清楚，不需要读长说明 |
| 父母有发起理由吗？ | 能自然说“这像我小时候玩的” |
| 孩子不懂怀旧也能玩吗？ | 规则和反馈足够直观 |
| UI 3 米外能看清吗？ | 分数、倒计时、站位和动作提示清楚 |
| 怀旧元素是否只是辅助？ | 去掉装饰后，场景动作理由仍成立 |
| 文案是否像现场语言？ | 不像技术提示或产品介绍 |
| 音乐音效是否原创安全？ | 不依赖真实老歌和真实 IP |
