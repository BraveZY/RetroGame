# 安卓大屏/摄像头验证切片

## 父级总任务

| 项目 | 内容 |
|---|---|
| 总任务 | 体感擦黑板 1-2 人 60 秒玩法闭环 |
| 子任务编号 | 07 |
| 覆盖范围 | 安卓大屏/电视盒子、普通摄像头输入、双人区分、输入延迟、大屏可读性和性能风险验证。 |

## 玩家可见结果

在安卓大屏/电视盒子和摄像头环境中，玩家能验证单人和双人的输入稳定性、大屏提示可读性，以及是否存在明显性能或交互阻塞。

## 需要实现的功能

- [ ] 准备安卓大屏/电视盒子验证入口或构建记录。
- [ ] 接入或替换为当前可用的摄像头体感输入 adapter。
- [ ] 验证单人手部/手臂轨迹能稳定驱动单人板擦。
- [ ] 验证双人站位能区分左板擦和右板擦。
- [ ] 记录输入丢失、延迟、遮挡、光照变化和身份混淆问题。
- [ ] 从 2-3 米距离检查目标提示、HUD、板擦和结算可读性。

## 隐含玩法语义

```text
真实玩家 -> 想在大屏前游玩 -> 进入设备验证环境 -> 摄像头识别手部/手臂轨迹 -> 轨迹驱动板擦完成任务 -> 系统暴露稳定性/延迟/可读性问题 -> 记录是否能进入正式设备实现
```

## 涉及系统

摄像头输入 adapter、安卓构建/运行、双人身份区分、性能观察、大屏 UI 可读性、设备验证记录。

## 涉及资源

沿用 01-06 的 Prototype/Placeholder 资源；需要设备验证截图、录屏或记录。无新增正式资源。

## 验收标准与证据

- [ ] 单人摄像头输入能在目标设备上驱动板擦完成至少 3 个目标或明确记录失败原因。（证据：设备录屏/设备记录）
- [ ] 双人摄像头输入能区分左板擦和右板擦，或明确记录身份混淆条件。（证据：设备录屏/设备记录）
- [ ] 2-3 米距离能看清当前任务提示、目标高亮、HUD 和结算主要信息，或记录需要调整的 UI 项。（证据：设备截图/人工流程）
- [ ] 记录输入延迟、输入丢失、遮挡、光照变化和性能卡顿的观察结论。（证据：设备记录/录屏/Profiler）
- [ ] 验证后给出是否可进入真实摄像头玩法实现的结论。（证据：Markdown 验证记录）

## 依赖关系

依赖 06 双人协作连击、贡献和结算。需要可用安卓大屏/电视盒子、普通摄像头和当前摄像头输入方案。

## 风险

设备、摄像头权限、输入插件或安卓性能可能阻塞。本切片允许输出“不可进入正式实现”的结论，但必须给出证据和最小解阻条件。
