## 总目标

| 项目 | 内容 |
|---|---|
| 玩家可见结果 | 玩家可以在 Unity Editor 中使用模拟体感输入完成 60 秒体感擦黑板；先单人跑通，再扩展双人协作，最后验证安卓大屏/摄像头风险。 |
| MVP 范围 | 准备、倒计时、单人板擦移动、目标提示、擦除判定、擦错反馈、计分、连击、结算、双人左右板擦、分工任务、共同擦除任务、设备验证。 |
| 明确不做 | 不做躲避玩法、沙包投掷/命中、隐藏找错、复杂文字识别、双人对抗、3 人及以上、剧情关卡、联网排行榜和长期养成。 |
| 验收口径 | 每个切片都必须能在 Editor、PlayMode、人工流程、录屏/截图、设备记录或测试中给出证据；真实摄像头只阻塞设备验证切片，不阻塞单人模拟输入闭环。 |

## 总体验收标准

- [ ] 玩家可以从准备界面进入 60 秒单人单局，并完成目标提示、擦除、擦错、计分、连击和结算。（证据：PlayMode 录屏或人工流程）
- [ ] 单人模式至少连续生成值日表/课程表、红圈错题错字、课间涂鸦三类任务，并能完成或失败。（证据：PlayMode 录屏或人工流程）
- [ ] 双人模式能区分左板擦/右板擦，并完成分工任务和共同擦除任务。（证据：PlayMode 录屏或人工流程）
- [ ] 双人结算能展示完成任务数、正确率、平均反应时间、最大协作连击、双人贡献和评级。（证据：截图/录屏）
- [ ] 安卓大屏/电视盒子设备验证记录已说明摄像头输入稳定性、双人区分和大屏可读性结论。（证据：设备记录/录屏/截图）

## 拆分边界

| 项目 | 内容 |
|---|---|
| 允许的前置任务 | 进入实现前可补 `game-design/blackboard-eraser/system-design/single-and-coop-eraser-loop/` 系统框架记录；这不是独立玩法切片，不单独作为子任务。 |
| 不允许横向拆分 | 不单独拆“所有代码”“所有 UI”“所有资源”“所有测试”；每个子任务必须连接到玩家可见体验。 |
| 占位资源策略 | 使用 `Placeholder_` 或 `Prototype_` 前缀资源验证绿色黑板、板擦、黑板内容、目标高亮、擦除遮罩、粉笔灰、HUD、铃声/口令和结算；正式资源接入前更新 GDD 或任务文档。 |

## 风险与约束

| 风险/约束 | 影响 | 应对 |
|---|---|---|
| 真实摄像头方案未定 | 可能影响输入延迟、双人区分和安卓性能。 | 01-06 使用模拟体感输入；07 单独验证设备。 |
| 擦除阈值和擦错惩罚未调优 | 可能影响公平性和爽感。 | 原型阶段保留参数记录，进入调参时更新 `balance/single-and-coop-eraser-loop/`。 |
| 大屏远距离可读性 | 目标和提示看不清会导致误判。 | 切片中使用大目标、高亮和人工 2-3 米走查。 |
| 系统边界未设计 | 可能导致玩法规则、MonoBehaviour、配置和测试 seam 混在一起。 | 实现前补系统框架记录，再进入 `game-unity-implementation`。 |
