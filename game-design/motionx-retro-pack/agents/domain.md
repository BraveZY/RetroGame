# MotionX Retro Pack 领域语言

## 权威来源与使用顺序

1. `Retro_Games_plans/docs/项目管理计划/MotionX-Retro-Pack-产品定义.md`：产品定位、用户、主题馆、首版范围与样板。
2. `Retro_Games_plans/docs/设计方案/游戏集合策划案/`：单个小游戏的 GDD。
3. `Retro_Games_plans/docs/单个复古体感游戏标准流程_参考.md`：单局通用体验流程。
4. `Retro_Games_plans/docs/待沟通确认事项.md`：尚未固化的美术、内容盘点与系统框架决定。

当资料冲突或新需求改变玩法/范围时，应先更新对应产品文档或建立 ADR；不要仅在代码注释、任务标题或本文件中悄悄改变定义。

## 核心术语

| 术语 | 当前定义 |
| --- | --- |
| MotionX Retro Pack / 复古体感包 | 面向亲子家庭的复古主题体感内容包装，不是单纯旧游戏换皮。 |
| 时光体感馆 / Time Play | 产品首页中的主题入口。 |
| 主题馆 | 以记忆和场景组织的内容层；包括童年操场、客厅街机、家庭电视健身等。 |
| 首批样板 | 操场木头人、电玩城投篮机、家庭电视健美操，用来验证主题和体感闭环。 |
| 入戏式识别 | 把识别/校准包装为场景行为，不直接以技术提示替代体验。 |
| 轻松反馈 | 失败不羞辱、信息清楚且短促的反馈方式。 |
| 同步感 | 粗粒度的家庭共同完成感；不等同于精确多人同步率。 |
| 2D 单目边界 | 不依赖精确地面落点、深度或高精度多人同步的体感能力边界。 |

## 不应写入本文件的内容

- 未确认的玩法规则、资产命名、技术接口、构建设置、SDK 能力或发布结论。
- 真实 IP、老歌、影视、品牌或人物的复刻方案；产品边界要求使用原创抽象化表达。
- 用户个人信息、账号、签名证书、密码或第三方平台凭据。

## ADR

- 当前未发现既有 ADR 目录或决策模板。
- 对会影响多个主题馆/小游戏的持久决定（例如统一流程、体感能力边界、内容接入规范、资源加载策略）应先与用户确认 ADR 的落点；不要把“待沟通确认事项”当作已生效决策。
