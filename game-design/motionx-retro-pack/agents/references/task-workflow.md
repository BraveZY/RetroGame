# 任务工作流

## 当前任务系统

- 已确认：当前工程任务使用本地 Markdown；已发现任务位于 `agent/task/`。
- 已发现示例：`agent/task/Task_手机平台设置实现任务_2026_6_17_1454.md`，使用全局状态、子任务看板、改动计划、验收状态、风险与回退等结构。
- 未确认：是否还有 GitHub、Jira、Tapd、飞书或其他外部任务系统。没有证据时，不应把它们当作当前任务的状态来源。

## 任务状态和证据

- 沿用现有文档中的 `完成`、`执行中`、`待验证`、`未开始`、`阻塞` 等状态；不要仅凭代码已写入就标记验收通过。
- 每项验收需写清可复核证据，例如 Unity Console、编译状态、EditMode/PlayMode 测试、场景/Prefab 回读、截图/录像、构建日志或明确的手动流程。
- 构建 dry-run、配置回读和脚本编译不等同于目标设备实际构建或试玩；在任务中分别记录。

## 后续新任务的最低字段

若新建可交付的产品/小游戏任务，遵循技能库的本地 Markdown contract，并补充：

- 父级目标或所属小游戏 GDD，以及本任务覆盖范围。
- 玩家可见结果和核心动作链；没有新增隐式玩法语义时明确写“无”。
- 涉及的系统、场景/Prefab/UI/音频/配置资产。
- 可逐项勾选的实现项与验收项；验收项须内联证据类型。
- 依赖、风险、回退和仍待用户确认的事项。

## Agent 权限

- Agent 可在用户明确委托的范围内创建或更新本地任务 Markdown，并如实回填已获得的验证证据。
- Agent 不得凭文档初始化推断外部系统状态、替用户确认发布签名、或把未执行的设备/构建验证勾为完成。
- 涉及 Scene、Prefab、Player Settings、Build Profile 的任务，必须将修改范围和验证结果写入任务或交付说明。
