## 总目标

| 项目 | 内容 |
|---|---|
| 玩家可见结果 | 玩家可选择单人、双人或三人进行 100 秒丢沙包对局；1P 躲避，投手由 AI 或 2P/3P 固定承担，结算明确显示阵营胜负。 |
| 变更范围 | 阵容、模式选择、共享键盘输入、投手瞄准和出手、100 秒规则、阵营胜负、HUD 与结算。 |
| 必须保持 | 45 度俯视 2D、单颗沙包、A/B 持球与接球循环、3 秒倒计时、命中扣 1 命、预警/轨迹、单人模拟输入和重开。 |
| 明确不做 | C 接球/反杀、局内换位、前后移动、下蹲/侧身、复杂骨骼、联网、多关卡剧情、长期养成与排行榜。 |
| 验收口径 | 三种模式均可完成一局；C 存活到 100 秒为躲避者胜，第三次受击为投手阵营胜；当前共享键盘中未参与模式的按键无效。 |
| 回归范围 | 单人 AI 传接、命中/躲避、倒计时、结算与重开；场景中的沙包不重复生成且不会卡死。 |

## 总体验收标准

- [ ] 单人、双人、三人均可选择正确阵容并进入 3 秒倒计时和 100 秒对局。（证据：PlayMode 录屏/人工流程）
- [ ] C 只能以 `A/D` 横向躲避；持球人类投手只能在所属 lane 内瞄准并按固定出手键出手。（证据：PlayMode 录屏/人工流程）
- [ ] 单颗沙包在 A/B 间传接；AI 与人类 owner 切换不导致重复生成或状态卡死。（证据：PlayMode 录屏/人工流程）
- [ ] 100 秒存活与第三次受击分别给出正确阵营胜负、C 评级和投手阵营命中数。（证据：PlayMode/自动化测试）
- [ ] 未参与当前模式的键盘输入不影响角色或沙包；后续体感接入时，识别丢失不暂停、不替换 AI。（证据：PlayMode/后续设备录屏）

## 切片边界

| 项目 | 内容 |
|---|---|
| 允许的前置工作 | 为阵容、输入 adapter 和单局规则建立可测试边界；不把真实摄像头 SDK 绑定到玩法规则层。 |
| 不允许的横向拆分 | 不创建“只写输入代码”“只做 HUD”或“只做资源”的任务。 |
| 占位资源策略 | 继续使用现有场景占位角色、沙包与 TextMesh；新增模式/分区/挥臂反馈先用占位 UI。 |
| 存档与兼容 | 当前无存档、联网或配置迁移；旧单人任务包不删除，作为回归基线。 |

## 风险与约束

| 风险/约束 | 影响 | 应对 |
|---|---|---|
| 单摄像头多人识别尚无真机证据 | 当前键盘验证不能等同真实多人体验。 | 05 后续在广角摄像头与安卓大屏环境验证。 |
| 现有规则/控制器是单人 60 秒实现 | 直接扩展会形成新的万能 Controller。 | 实现前完成整个 epic 的系统设计。 |
| 用户选择不暂停且不替换 AI | 丢失识别会直接影响胜负公平性。 | HUD 明示角色失效；把该行为写入设备验收。 |
