## 玩家可见结果

玩家使用同一键盘：1P 只控制 C 左右躲避，2P/3P 在投手 lane 内左右瞄准并按出手键；未进入当前模式的按键无效。

## 需要实现的功能

- [x] 输入 adapter 提供按 owner 区分的横向位置和一次性出手请求；键盘映射为 1P `A/D`、2P `J/L + I`、3P `←/→ + ↑`。
- [x] 按当前模式启用对应玩家输入；未参与模式的按键必须无效。
- [x] C 仅在中间躲避区 X 轴移动；人类投手仅在自己的 lane 内横向瞄准。
- [x] 为后续摄像头 adapter 保留可提供横向位置、挥臂请求和识别状态的输入数据形状，但当前不接入设备。
- [x] 显示当前模式、输入活动和出手请求的占位反馈。

## 本轮实现记录

- `KeyboardDodgeballInput` 是键盘 adapter；控制器只向它查询 C 横移、投手横移和出手请求。
- `DodgeballSession.GetThrowerControl` 在单人时禁用 2P/3P，在双人时禁用 3P；C 仅使用 X 轴。

## 隐含玩法语义

`键盘按键 -> 当前模式过滤 -> owner 读取横向状态 -> C 移动或投手瞄准 -> 出手请求 -> 持球门控 -> 场景反馈`；未来体感 adapter 复用同一输入数据形状。

## 涉及系统

输入 adapter、玩家阵容、场景角色移动、投手出手门控、HUD、EditMode/PlayMode 测试。

## 现有行为影响与保护

影响 `PlayerMover2D` 与 `SinglePlayerReadyFlowController.UpdatePlayerMovement` 的全轴键盘输入；必须保持单人 `A/D` 横移稳定，且不让非当前模式的键或出手请求生成额外沙包。

## 涉及资源

现有角色/场地占位物；新增 `Placeholder_` 分区、输入状态和挥臂提示 UI。

## 验收标准与证据

- [ ] 1P 的 `A/D` 输入只改变 C 的 X 轴，且不会越出躲避区。（证据：PlayMode 录屏）
- [ ] 双人/三人模式下，人类投手只在自己的 lane 内横向瞄准；未持球或未参与当前模式时按出手键不产生出手请求。（证据：PlayMode 录屏/自动化测试）
- [ ] 当前共享键盘模式不依赖摄像头、识别丢失或暂停逻辑。（证据：PlayMode/代码检查）
- [x] 后续真实广角摄像头可替换键盘 adapter，而不改动回合或沙包规则 API。（证据：代码检查；设备验证后置）

## 回归检查

- [ ] 单人模拟输入仍可连续横移，输入停止后不跳变。（证据：PlayMode）
