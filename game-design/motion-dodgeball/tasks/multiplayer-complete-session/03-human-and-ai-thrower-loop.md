## 玩家可见结果

当前持球投手的出手方式符合阵容：人类投手瞄准并按出手键后出手，AI 投手按预警节奏出手；沙包未命中 C 后由对侧投手接住同一颗沙包并切换持球权。

## 需要实现的功能

- [x] 持球权同时关联 A/B 身份与当前人类/AI owner，避免用独立脚本重复管理投掷。
- [x] 人类持球时显示预警和可出手状态；仅在当前模式的出手键请求时释放沙包。
- [x] AI 持球时保留预警、瞄准、自动投掷与难度节奏。
- [x] 沙包从持球者出发，飞向 C；未命中后由对侧接球、切换持球权；异常越界或超时可恢复且不复制沙包。
- [x] 显示持球 owner、投掷预警、按键出手与接球的占位反馈。

## 本轮实现记录

- 复用既有 `SandbagState` 单颗沙包状态机；`currentHolder` 结合 `DodgeballSession` 决定当前投手是 AI 还是玩家。
- AI 在预警结束后出手；人类 A 用 `I`、人类 B 用 `↑` 出手。预警轨迹复用现有场景对象。

## 隐含玩法语义

`持球投手 -> 判断 owner -> 人类瞄准/按键或 AI 预警/计时 -> 出手 -> 单颗沙包飞行 -> C 命中或越过 -> 对侧接球 -> 持球权切换 -> 下一轮`。

## 涉及系统

阵容 owner、输入 adapter、沙包状态机、AI 投手行为、场景角色表现、预警/轨迹、难度参数、PlayMode 测试。

## 现有行为影响与保护

影响 `SinglePlayerReadyFlowController` 的 `UpdateThrowers`、`UpdateSandbag`、持球状态和 AI 自动计时；必须保留单人 A/B AI 自动投掷与接球、单颗沙包和异常恢复。

## 涉及资源

复用现有 `Prototype_` 沙包、投手占位物和预警对象；人类持球/挥臂状态允许使用 `Placeholder_` 文本或简单高亮。

## 验收标准与证据

- [ ] 单人模式中 A/B 均按 AI 预警节奏投掷、接球和切换持球权。（证据：PlayMode 录屏）
- [ ] 双人模式中 2P-A 持球时必须由 `I` 出手，AI-B 持球时自动出手。（证据：PlayMode 录屏/自动化测试）
- [ ] 三人模式中 2P-A 或 3P-B 持球时都只有对应玩家可通过 `I` 或 `↑` 出手。（证据：PlayMode 录屏/自动化测试）
- [ ] 连续三局不会生成多颗沙包，也不会在接球、超时或识别丢失时卡死。（证据：PlayMode 录屏）

## 回归检查

- [ ] 单人 AI-A/AI-B 的预警、轨迹、接球、异常重置和难度节奏仍可用。（证据：PlayMode 录屏）
