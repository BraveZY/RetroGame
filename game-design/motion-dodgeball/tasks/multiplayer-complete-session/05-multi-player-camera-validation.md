# 单摄像头多人识别设备验证

## 父级总任务

| 项目 | 内容 |
|---|---|
| 总任务 | [体感丢沙包 1-3 人完整单局](00-epic.md) |
| 子任务编号 | 05 |
| 覆盖范围 | 广角摄像头的左/中/右分区、横向移动、挥臂、识别丢失和安卓大屏可读性验证。 |

## 玩家可见结果

在目标设备上，1-3 名玩家能理解各自站位和角色，并看到横向移动、投手挥臂、识别丢失与沙包轨迹的反馈；验证不会把失去识别误判为暂停或 AI 接管。

## 需要实现的功能

- [ ] 提供可替换真实摄像头 adapter 的接入点与校准/分区状态展示，不在本任务绑定未选定 SDK。
- [ ] 使用真实广角摄像头执行单人、双人、三人站位、横移和投手挥臂验证。
- [ ] 验证 C、投手和不同分区丢失识别时的“不暂停、不替换”表现。
- [ ] 在安卓大屏/电视盒子确认模式、分区、预警、轨迹、时间、生命和胜负文本可读。
- [ ] 保存录屏或设备记录；若识别方案尚不可用，明确记录阻塞和仍可通过 Editor 证明的范围。

## 隐含玩法语义

`玩家站入分区 -> 身份锁定 -> 横移/挥臂 -> 场景反馈 -> 暂时离开画面 -> 对应角色失效且对局持续 -> 返回画面 -> 操作恢复`。

## 涉及系统

摄像头 adapter、横向分区、输入状态 HUD、Android 大屏场景、录屏/设备记录、性能与可读性检查。

## 现有行为影响与保护

不改变回合或沙包规则层；必须保持 Editor 模拟输入可作为无摄像头环境下的回归路径。

## 涉及资源

广角摄像头、安卓大屏/电视盒子、现有场景与 HUD；无新增正式美术资源。

## 验收标准与证据

- [ ] 单人、双人、三人均可在真实摄像头下锁定预期横向分区。（证据：设备录屏）
- [ ] 2P/3P 的明显挥臂可在持球时触发一次出手，且不在未持球时误触发。（证据：设备录屏）
- [ ] C 或投手丢失识别时，对局不暂停、AI 不接管，并在返回分区后恢复对应输入。（证据：设备录屏）
- [ ] 安卓大屏上可从远距离读出模式、时间、生命、预警和结算胜负。（证据：设备截图/录屏）

## 回归检查

- [ ] 未连接摄像头时，Editor 模拟输入仍可完成单人回归流程。（证据：PlayMode）

## 依赖

依赖 02、03、04；需要可用广角摄像头、目标 Android 大屏/电视盒子及选定输入 adapter。

## 风险

真实摄像头 SDK、设备权限与实际光照背景目前未确认；若缺少设备或 adapter，本任务状态应保持“需要设备验证”，不得把 Editor 结果标记为通过。
