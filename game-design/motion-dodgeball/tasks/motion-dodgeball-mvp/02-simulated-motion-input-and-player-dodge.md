## 玩家可见结果

玩家可以用开发期模拟输入控制中间躲避者 C，在中间躲避区内左右/前后移动，并看到角色位置随输入实时变化。

## 需要实现的功能

- [ ] 一个模拟体感输入源，用于替代未确认的真实摄像头方案。
- [ ] 玩家位置到中间躲避区的映射。
- [ ] 躲避区边界限制，防止玩家角色离开玩法区域。
- [ ] 输入丢失或超出范围的简单提示占位。
- [ ] 为后续真实摄像头输入预留可替换的输入层边界。

## 涉及系统

- 体感输入抽象
- 玩家映射
- 躲避区边界
- UI 提示

## 涉及资源

- 躲避者 C 占位角色
- 躲避区边界表现
- 输入状态提示 UI

## 验收标准

- [ ] 使用模拟输入可以控制躲避者 C 左右移动。（证据：PlayMode/录屏/人工流程）
- [ ] 使用模拟输入可以控制躲避者 C 前后移动。（证据：PlayMode/录屏/人工流程）
- [ ] 躲避者 C 不会离开中间躲避区。（证据：PlayMode/录屏/人工流程）
- [ ] 输入停止时角色保持在合理位置，不出现跳变。（证据：PlayMode/录屏/人工流程）
- [ ] 超出模拟输入范围时有可见提示或边界反馈。（证据：PlayMode/录屏/人工流程）
- [ ] 当前切片不接入真实摄像头、不做精细骨骼识别。（证据：代码/配置检查）

## 风险

- 模拟输入如果和未来摄像头输入差异太大，后续替换成本会升高。
- 移动范围和场地透视不匹配时，玩家会感觉角色位置不自然。
