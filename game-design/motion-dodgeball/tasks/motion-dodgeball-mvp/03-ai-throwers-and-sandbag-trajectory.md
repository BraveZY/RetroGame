## 玩家可见结果

上下两侧 AI 投手不再是独立发射器，而是围绕同一颗沙包循环传接：持球投手向躲避者 C 投掷，C 未被击中时对侧投手主动接住沙包并成为下一名持球投手，轨迹在大屏视角下清晰可见。

## 需要实现的功能

- [x] 上侧投手 A 和下侧投手 B 作为角色存在，支持持球、投掷、接球和等待状态。
- [x] 当前持球投手根据躲避者 C 的当前位置瞄准并投出沙包。
- [x] 沙包按单颗运行态处理，记录当前持球者、飞行方向和接球目标，不再让 A/B 各自生成新沙包。
- [x] 沙包未击中 C 后，对侧接球投手主动移动到接球点并接住沙包。
- [x] 接球成功后持球权切换到接球投手，并进入下一轮预警/投掷。
- [x] 接球失败或沙包越界时，沙包重置到预期持球投手，避免场上卡死。
- [x] 投掷前的预警表现。
- [x] 沙包轨迹可视化，如拖尾、影子或方向提示。
- [x] 简单难度曲线：随时间轻微提高速度或缩短间隔。

## 验收标准

- [ ] A 持球时可以向躲避者 C 投出沙包。（证据：UnityCaptain/录屏/人工流程）
- [ ] B 持球时可以向躲避者 C 投出沙包。（证据：UnityCaptain/录屏/人工流程）
- [ ] 只有当前持球投手负责瞄准和出手，另一个投手在未命中后作为接球投手行动。（证据：UnityCaptain/录屏/人工流程）
- [ ] 沙包未击中 C 后，对侧投手会主动移动并接住同一颗沙包，而不是重新生成一颗沙包。（证据：UnityCaptain/录屏/人工流程）
- [ ] 接球成功后持球权切换，下一轮从接球投手位置投出。（证据：UnityCaptain/录屏/人工流程）
- [ ] 投掷前有可见预警。（证据：截图/录屏/人工流程）
- [ ] 沙包轨迹在 16:9 大屏视图下清晰可见。（证据：截图/录屏/人工流程）
- [ ] 连续观察 3 局，A/B 传接和投掷节奏稳定且不会卡住。（证据：录屏/人工流程）
- [ ] 03 验收不以命中判定、扣生命或结算为完成条件；这些结果继续由 04/05 追踪。（证据：任务范围检查）

## 风险

- 沙包速度过快会让玩家觉得不公平，过慢则缺少压力。
- 接球点和接球速度如果不清楚，会让 A/B 看起来仍像发射器而不是角色。
- 45 度视角下轨迹如果不够明显，玩家难以判断沙包是否会命中。
