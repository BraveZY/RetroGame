# 体感丢沙包 GDD

## 概述

| 项目 | 内容 |
|---|---|
| 一句话定位 | `童年操场`主题馆中的 1-3 人复古 2D 体感丢沙包子游戏：1P 在 100 秒内横向躲避上下两侧投手传接并投来的沙包。 |
| 目标体验 | 规则一眼能看懂，玩家以左右身体移动躲避，围观者能清楚看到投掷、躲避、命中和结算。 |
| 当前实现目标 | 先以共享键盘完成 1-3 人完整闭环：模式选择、准备、倒计时、投手投掷、玩家躲避、命中扣生命、100 秒结算与重开；体感后续接入。 |
| 单局时长 | 100 秒。 |

## 目标玩家与平台

| 项目 | 内容 |
|---|---|
| 目标玩家 | 家庭客厅、亲子娱乐、线下活动试玩的 1-3 人用户。 |
| 当前验证平台 | Unity Editor + 共享键盘；安卓大屏/电视盒子与摄像头体感为后续验证环境。 |
| 验证环境 | 优先在 Unity Editor 用键盘验证 1-3 人完整闭环，再在安卓大屏/电视盒子和普通摄像头环境验证体感输入。 |
| 当前输入方式 | 同一键盘：1P-C 为 `A/D`，2P-A 为 `J/L + I`，3P-B 为 `←/→ + ↑`；未参与当前模式的按键无效。 |

## 核心循环

| 步骤 | 玩家行为 | 系统反馈 | 推进条件 |
|---|---|---|---|
| 1 | 玩家选择人数模式并查看固定角色。 | 屏幕显示 1P/2P/3P 的角色归属和准备状态。 | 玩家确认开始。 |
| 2 | 玩家进入中间躲避区等待倒计时。 | 上下两侧投手就位，显示 3 秒倒计时。 | 倒计时结束。 |
| 3 | 玩家观察持球投手动作和沙包预警。 | 当前持球投手从上侧或下侧向 C 投出沙包。 | 沙包进入中间区域。 |
| 4 | C 通过 `A/D` 左右躲避；人类投手在各自 lane 内以固定按键瞄准并出手。 | 沙包轨迹、擦身反馈、躲避次数实时更新。 | 沙包离开判定区或命中 C。 |
| 5 | C 被命中或成功躲避。 | 命中时扣生命并播放反馈；未命中时对侧投手接住沙包并成为下一名持球投手。 | 生命大于 0 且时间未结束。 |
| 6 | 玩家坚持到 100 秒结束或第三次受击。 | 显示剩余生命、躲避次数、命中次数、A/B/C 评级和课间称号。 | 进入结算界面。 |

## 操作与交互

| 操作/状态 | 规则 | 反馈 | 失败或重试 |
|---|---|---|---|
| 站位准备 | 玩家需要进入中间识别区域。 | 显示轮廓/中心点和准备提示。 | 未识别到玩家时保持等待。 |
| 左右移动 | 1P 以 `A/D` 映射到场地中间躲避区的 X 轴。 | 屏幕角色同步左右移动。 | 超出边界时显示边界反馈。 |
| 不使用的动作 | 当前不将摄像头、前后移动、下蹲、侧身或精细手势作为输入。 | 不出现要求这些动作的教学或判定。 | 先验证多人规则与键盘可玩性。 |
| 被沙包命中 | 沙包与玩家轮廓/碰撞区重叠时判定命中。 | 扣 1 条生命、受击闪烁、音效和短暂停顿。 | 初始 3 条生命；第三次命中则提前结算。 |
| 躲避成功 | 沙包穿过中间躲避区但未命中 C。 | 躲避次数增加，对侧投手进入接球并准备下一次投掷。 | 对侧投手未接住时可重置到持球状态。 |
| 投手出手 | 当前持球的人类投手在所属 lane 内以 2P `J/L + I` 或 3P `←/→ + ↑` 瞄准并出手。 | 显示投掷预警、出手动作与沙包轨迹。 | 未持球或未参与当前模式的投手不能出手；AI 投手按 AI 节奏投掷。 |

## 系统模块

| 系统 | 职责 | 完整单局范围 | 不做 |
|---|---|---|---|
| GameSessionManager | 协调人数模式、键盘输入入口、阵容、倒计时、对局、结算与重开。 | 作为该子游戏的单局流程 owner；不拥有投掷、沙包飞行或 HUD 的具体规则。 | 不做游戏包级全局 Manager、Singleton、事件总线或 Service Locator。 |
| 玩家阵容 | 定义角色 owner：单人是 1P-C + AI-A + AI-B，双人是 1P-C + 2P-A + AI-B，三人是 1P-C + 2P-A + 3P-B。 | 角色在一局内固定，不轮换。 | 不做局内角色交换。 |
| 键盘输入 | 提供按 PlayerSlot 区分的横向输入和一次性出手请求。 | 支持 `A/D`、`J/L + I`、`←/→ + ↑`。 | 不做摄像头接入、精细手势或纵深位置判定。 |
| AI 投手 | 控制上下两侧投手的持球、投掷和接球。 | 一颗沙包在 A/B 间传接；持球投手投向 C，未命中时对侧投手接球并成为下一名持球投手。 | 不做复杂 AI 策略或角色成长。 |
| 沙包轨迹 | 管理沙包持有、飞行、命中、接球和重置。 | 清晰轨迹、预警、命中判定、躲避判定、A/B 接球判定。 | 不做真实复杂物理或 C 接球反杀。 |
| 生命与评级 | 记录生命、躲避次数、命中次数和最终评级。 | 100 秒限时生存，初始 3 命，第三次命中淘汰；结算给出 A/B/C。 | 不做连击、掉落道具、长期养成、排行榜或联网分数。 |
| UI 流程 | 支持模式选择、入场、横向校准、准备、倒计时、游玩 HUD、结算和重开。 | 本地单局完整流程；结算显示“课间小冠军 / 躲闪小能手 / 再来一局”。 | 不做账号、设置页、商城、剧情界面。 |

## 关卡或单局流程

| 阶段 | 内容 | 目标 | 验证点 |
|---|---|---|---|
| 准备 | 选择人数模式并查看按键说明。 | 降低角色归属误解。 | 玩家可理解自己控制哪个角色。 |
| 倒计时 | 显示投手站位和 3 秒倒计时。 | 给玩家建立空间关系。 | 上下投手和中间躲避区清楚。 |
| 前 30 秒 | 沙包速度较慢，投掷间隔较长。 | 让玩家熟悉横向躲避规则。 | 新玩家能完成基础躲避。 |
| 30-70 秒 | 投掷频率提升，上下交替更明显。 | 形成持续压力。 | 玩家需要主动观察投手方向。 |
| 70-100 秒 | 速度或频率小幅提升。 | 制造收尾紧张感。 | 难度提升但不依赖精细动作。 |
| 结算 | 展示剩余生命、躲避次数、命中次数、A/B/C 评级和课间称号。 | 形成可复玩目标。 | 玩家能快速理解表现并重开。 |

## 角色、敌人、道具

| 对象 | 作用 | 状态/属性 | 备注 |
|---|---|---|---|
| 躲避者 C | 1P 控制的中间小学生角色。 | 3 条生命、横向位置、轮廓/碰撞区、受击状态。 | 三种人数模式中均由 1P 控制。 |
| 上侧投手 A | 上侧投手。 | 持球、投掷准备、投掷、接球、等待。 | 单人由 AI 控制；双人和三人由 2P 控制。 |
| 下侧投手 B | 下侧投手。 | 持球、投掷准备、投掷、接球、等待。 | 单人和双人由 AI 控制；三人由 3P 控制。 |
| 沙包 | 主要危险物。 | 持有者、速度、方向、轨迹、命中状态、接球状态。 | 完整单局按单颗沙包循环，轨迹必须在大屏上清晰。 |
| 躲避区 | 玩家活动区域。 | 45 度俯视 2D 场地中央的横向区域。 | 仅允许 C 沿 X 轴移动，避免把纵深作为体感判定。 |

## UI 信息结构

键盘多人模式的完整交互流程、ASCII 线框原型、键位提示、HUD 及结算规范见：
`game-design/motion-dodgeball/ui/multiplayer-complete-session/references/UI-HUD-FLOW-SPEC.md`。

| 界面/区域 | 信息 | 交互 | 备注 |
|---|---|---|---|
| 入场与准备界面 | 模式、键盘按键说明和开始提示。 | 玩家确认模式后开始。 | 使用“准备上场”等场景语言，面向大屏远距离阅读。 |
| 游戏 HUD | 剩余时间、生命、躲避次数、命中次数。 | 无复杂操作。 | 信息应放在不遮挡沙包轨迹的位置。 |
| 投掷预警 | 投手动作、方向提示、沙包起手反馈。 | 无。 | 需要比文字更依赖动作和图形。 |
| 命中反馈 | 受击闪烁、生命变化、短音效。 | 无。 | 反馈清楚但不长时间打断。 |
| 结算界面 | 剩余生命、躲避次数、命中次数、A/B/C 评级、课间称号、再来一局。 | 支持重开。 | A 级“课间小冠军”、B 级“躲闪小能手”、C 级“再来一局”；适合线下活动快速轮换。 |

## 美术与音频需求

| 类型 | 资源 | 数量/状态 | 命名或导入规则 |
|---|---|---|---|
| 角色 | 原创小学生三人组：躲避者 C、投手 A、投手 B。 | 3 个角色位，可先用原型资源。 | 动作夸张、轮廓清楚；原型资源使用 `Prototype_` 前缀。 |
| 场景 | 明亮干净的童年操场，45 度俯视 2D。 | 1 个首版场地。 | 粉笔躲避区清楚，上下投手位明确；怀旧点缀不得压过动作空间。 |
| 道具 | 沙包。 | 1 个核心道具。 | 需要明显颜色和飞行拖尾/轨迹。 |
| UI | 模式选择、入场、横向校准、HUD、结算、识别提示。 | 完整单局必需。 | 大屏可读，避免遮挡中间区域。 |
| 特效 | 投掷预警、擦身、命中、结算评级。 | 可先使用简化特效。 | 优先服务反馈清晰度。 |
| 音频 | 原创下课铃、原创短口哨、投掷、飞行、命中、躲避成功、结算。 | 下课铃用于入场；短口哨用于倒计时与投掷预警。 | 可先使用占位音效，但不得使用真实校园铃声、现成音乐或可识别 IP 音效。 |

## 技术和制作约束

| 约束 | 原因 | 影响 |
|---|---|---|
| 安卓盒子性能有限 | 首发环境不是高性能 PC。 | 视觉、识别和特效需控制复杂度。 |
| 普通摄像头识别不稳定 | 家庭和活动现场光照、背景、距离不可控。 | 体感后续只依赖横向位置或足以稳定得到横向位置的大致轮廓，不依赖精细骨骼。 |
| 体感输入存在延迟 | 躲避类玩法对公平性感知敏感。 | 沙包速度、预警时间和碰撞区需要给容错。 |
| 大屏远距离观看 | 玩家和围观者都需要快速读懂状态。 | UI 字号、沙包轨迹、角色剪影必须清晰。 |
| 当前样例项目优先 Editor 验证 | 项目现有构建目标声明当前不要求发布构建。 | 先完成 Editor 内闭环，再扩展 Android 真机验证。 |

## 验收标准

| 编号 | 标准 | 验证方式 |
|---|---|---|
| A1 | 单人、双人、三人均可从入场与横向校准进入 100 秒单局。 | Editor 手动验证。 |
| A2 | 上下两侧投手能围绕同一颗沙包完成投掷、未命中后的接球和下一次投掷；人类投手可横向瞄准并按固定键出手，AI 投手按节奏出手。 | 观察至少 3 局，确认 A/B 持球权、接球和节奏稳定。 |
| A3 | 1P 的 `A/D` 能映射到中间躲避区的 X 轴；2P/3P 的固定按键只影响自己的投手 lane。 | PlayMode/自动化测试验证移动响应。 |
| A4 | 沙包命中玩家时扣 1 条生命并触发明确反馈；第三次命中提前结算。 | 手动制造连续命中场景。 |
| A5 | 沙包未命中 C 并被对侧投手接住时计为躲避成功。 | 手动躲避至少 10 次并核对计数。 |
| A6 | 100 秒结束后显示剩余生命、躲避次数、命中次数、A/B/C 评级和课间称号。 | 完整游玩一局。 |
| A7 | 第三次受击时可以提前结算。 | 连续命中直到生命为 0。 |
| A8 | 大屏远距离下能看清投手、躲避者、沙包轨迹和核心 HUD。 | 安卓大屏或等效显示环境走查。 |
| A9 | 未参与当前模式的键盘按键不影响角色或沙包；摄像头分区与识别丢失为后续设备验收。 | PlayMode/自动化测试。 |

## 明确不做

| 不做项 | 原因 |
|---|---|
| C 接沙包/反杀 | 会改变玩家输入要求，增加精细动作识别压力；A/B 接球属于 AI 投手循环，属于当前完整单局。 |
| 复杂骨骼识别 | 普通摄像头和安卓盒子环境下风险高。 |
| 联网 | 当前子游戏聚焦本地单局体验。 |
| 多关卡剧情 | 当前目标是验证体感躲避闭环，不做内容扩张。 |
| 长期养成和排行榜 | 会增加数据、账号和运营需求，不服务首版验证。 |
