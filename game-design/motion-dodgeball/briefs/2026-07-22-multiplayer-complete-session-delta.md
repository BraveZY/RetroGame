# 1-3 人完整单局功能增量简报

| 项目 | 内容 |
|---|---|
| 当前游戏/版本状态 | 场景已具备单人躲避、AI 投手、单颗沙包和基础结算原型；`SinglePlayerReadyFlow`、`SinglePlayerReadyFlowController` 及现有任务包仍以单人 60 秒为实现和任务口径。 |
| 玩家可见变更 | 游戏支持单人、双人、三人固定阵容；单局为 100 秒，1P 永远为躲避者 C，投手玩家可横向瞄准并挥臂出手。 |
| 阵容规则 | 单人：1P-C + AI-A + AI-B；双人：1P-C + 2P-A + AI-B；三人：1P-C + 2P-A + 3P-B。角色在一局内不轮换。 |
| 胜负与结算 | C 存活到 100 秒则躲避者胜；第三次受击则投手阵营胜。结算显示 C 的 A/B/C 生存评级与投手阵营命中数。 |
| 当前输入与设备 | 先使用同一键盘：1P-C 为 `A/D`，2P-A 为 `J/L + I`，3P-B 为 `←/→ + ↑`；未参与当前模式的按键无效。 |
| 后续体感边界 | 广角摄像头的左/中/右分区、横移与挥臂保留为后续 adapter；识别丢失时不暂停、不替换 AI。 |
| 必须保持的既有行为 | 45 度俯视 2D 场地；上下 A/B 围绕同一颗沙包投掷、未命中后接球并切换持球权；3 秒倒计时；命中扣 1 命；场景内可见预警、轨迹、HUD 与重开。 |
| 受影响模块 | 回合规则与结算、阵容/角色 owner、输入抽象、投手出手门控、AI 兜底、沙包状态机、HUD、模式选择/入场校准、EditMode 与 PlayMode 测试。 |
| 场景/Prefab/资源影响 | `MotionDodgeball.unity`、投手/躲避者占位物、HUD 文本与模式选择 UI；需要玩家分区与挥臂状态的可视反馈。当前单颗沙包 Prefab 可复用。 |
| 存档/兼容影响 | 当前没有存档、账号或联网数据；无需数据迁移。 |
| 明确不做 | C 接沙包/反杀、局内换位、前后移动、下蹲/侧身输入、复杂骨骼、联网、多关卡剧情、长期养成与排行榜。 |
| 回归范围 | 单人模式必须仍可通过模拟输入完整游玩；AI-A/AI-B 传接循环、生命/命中/躲避统计、倒计时、结算与重开不可退化；多人横向分区与丢失识别须在摄像头环境验证。 |
| 验收方向 | 三种模式均能锁定正确阵容并完成 100 秒对局；人类投手只有持球时可挥臂出手；阵营胜负和结算数据正确；识别丢失严格遵守“不暂停、不替换”规则。 |
| 主要风险 | 当前共享键盘适合功能验证但不等同家庭体感体验；普通广角摄像头对 3 人横向分区和挥臂仍无设备证据，需保留可替换输入 adapter。 |
| 推荐下一技能 | `game-task-triage`，将旧单人任务包替换为可验证的完整子游戏任务包。 |
